# Браузерный плагин: что это, зачем и как устроено

Единая точка входа. Здесь — вся картина целиком: почему библиотека появилась, почему у
неё такая форма, что она умеет сегодня и как оказалась частью этого репозитория.
Подробности, которые в общий рассказ не влезли, лежат рядом:

| Файл | О чём |
|---|---|
| `DESIGN.md` | принятые решения, диагностики D-B-xx и открытые вопросы |
| `REUSE.md` | что взято у ядра и какие дефекты были у плагина до приведения к его форме |
| `PLAN.md` | этапы B0–B6: как плагин получил форму ядра, шаг за шагом, с доказательствами |
| `CORE_DEBT.md` | долг ядра, найденный плагином: задачи не для плагина |
| `decisions.md` | протокол трёх спайков — исторический, с именами тех дней |
| `MERGE.md` | слияние с `eazy-sdk`: совместимость, шаги, найденные дефекты |

Руководство для пользователя — раздел «Браузер» сайта документации
(`docs-site/src/content/docs/guides/browser/`).

---

## 1. С чего начиналось

Был браузерный SDK, написанный императивно: россыпь маленьких приватных методов-шагов,
селекторы внутри методов, `if`-ы на каждый исход. Читать его было тяжело не из-за объёма,
а из-за того, что **намерение не отличалось от техники**: `_click_submit_button` и
`_wait_for_dialog` стояли в коде рядом и выглядели одинаково важными.

Задачу разбили на три этапа:

1. найти эталон — чужой браузерный SDK с хорошей формой;
2. придумать декларативное описание по образцу `eazy-sdk`;
3. сделать стайл-чекер, который не даст съехать обратно.

Эталонами выбраны **Geb** (Groovy) и **web-poet** (Python): у первого взяты `static at`
(условие готовности страницы), `static content` (карта элементов) и типизированный
переход `to: ResultsPage`; у второго — `ItemPage[Item]` и `@field`. Этапы 1 и 2
закрыты, этап 3 — нет (`DESIGN.md` §8).

Ключевая мысль, из которой выросло всё остальное: **то же, что `eazy-sdk` делает для
HTTP, нужно браузеру**. Там операция описана классом-контрактом — путь, случаи ответа,
типизированные отказы; здесь должно быть так же, только вместо ответа сервера —
страница.

## 2. Как это читается

```python
class CompaniesPage:
    """Список компаний. Формы создания здесь нет — её ещё нет на странице."""

    create_button: Annotated[Element, css('button[data-test="create"]')]
    filters: Annotated[FilterPanel, region(FilterPanel, root=css("form.filters"))]


@dataclass(frozen=True, slots=True, kw_only=True)
class OpenCreateCompany(BrowserOperation[CompaniesPage, CreateCompanyDialog]):
    """Открыть форму создания компании."""

    __browser__ = Browser.act(
        CompaniesPage,
        at=css('button[data-test="create"]'),
        outcomes=outcomes(
            when(visible(css('div[role="dialog"]')), to=CreateCompanyDialog),
            otherwise=_dialog_missing,
        ),
    )

    async def act(self, content: CompaniesPage) -> None:
        await content.create_button.click()


class CompaniesPortal(AsyncBrowserApi):
    errors = PORTAL_ERRORS

    open_create_company = op(OpenCreateCompany)
    submit_company = op(SubmitCompany)


dialog = await CompaniesPortal(AsyncBrowserClient(driver)).open_create_company()
```

Что здесь объявлено, а не написано руками:

* **карта элементов** — аннотациями. Опечатка в имени поля ловится типизатором, а поле без
  маркера — при импорте (D-B-03);
* **условие готовности** (`at=`) — раннер проверит его до действия, и автор операции не
  может про него забыть;
* **исходы** — таблицей «признак → исход». Union выводится из объявления и сверяется с
  типом операции (D-B-08): объявить исход и забыть его в типе нельзя;
* **переход** — успех это не `True`, а состояние `CreateCompanyDialog`. Оно держит роутер и
  отправляет форму его же операцией `submit_company`: пока исход не разобран, следующего
  шага в типах просто нет;
* **правила портала** — `errors = PORTAL_ERRORS` один раз на роутер, как
  `errors = SERVICE_ERRORS` у HTTP-роутера ядра.

Всё объявление операции — одно значение `__browser__`, как `__http__` у HTTP-операции, а
опубликована она тем же `op()`. Второй глагол — переход:
`Browser.goto("/companies/{company_id}", at=css("h1.company"))`, и тело такой операции — сам
переход. Императив остаётся только внутри `act`, и там ровно те шаги, которые делает
человек.

## 3. Устройство

```
eazy_sdk_browser/
  spec.py         Browser.act / Browser.goto — единственная спека операции
  operations.py   BrowserOperation, раннер, диагностики D-B-xx
  api.py          AsyncBrowserApi: роутер, дескриптор, сервисные атрибуты
  client.py       AsyncBrowserClient, BrowserClientConfig, BrowserCallOptions, execute
  outcomes.py     outcomes / when, состояния из роутера
  conditions.py   признаки страницы и снимок Observation
  locators.py     css / any_of / last, коллекции each, шаблоны с экранированием
  content.py      сборка карты из аннотаций, подкарты region
  driver.py       протокол Driver и Element — минимум, который умеют все
  navigation.py   адрес Browser.goto, переходы как события, признак navigated()
  network.py      ответы страницы: response.arrived, ApiResponse
  rich_text.py    редактор форматированного текста — возможность rich_text
  failures.py     правила отказа страницы
  interceptors.py помехи: увидел баннер — закрой и продолжай
  login.py        объявление входа BrowserLogin и мост в HTTP-Auth
  session.py      BrowserSession: сессия одного контекста на SessionLifecycle ядра
  state.py        состояние сессии: куки и localStorage, протокол StateAware
  fetch.py        запрос, выполненный изнутри страницы
  profile.py      возможности драйвера и проверка до запуска
  errors.py       BrowserError и BrowserDeclarationError
  testing.py      драйверы для тестов: страница без браузера
  handlers/       адаптеры: playwright (selenium, camoufox, pydoll — следующие), CapturePolicy
  integrations/   хранилище аккаунтов, разбор ответов eazy-sdk, BrowserHandler
```

Пять правил, которые держат эту раскладку и **проверяются** `import-linter`, а не
подразумеваются (`DESIGN.md` §7):

1. ядро плагина не знает ни одного драйвера;
2. ядро плагина не знает ни собственных интеграций, ни `eazy_sdk_accounts` — хранилище и
   разбор ответов приходят протоколом. Ядро `eazy_sdk` ему доступно: ошибки, профиль
   возможностей, `op()` и жизненный цикл сессии — общие;
3. `eazy_sdk` не знает браузера. Зависимость односторонняя;
4. общее хранилище аккаунтов не знает ни браузера, ни HTTP-транспорта;
5. ядро плагина не знает модуля `session`: жизненный цикл сессии живёт только там, а клиент
   знает лишь протокол `SessionSource`.

Шестое правило — граница слоёв (`LAYERS.md`): плагин знает сайт, а не среду. Он не
запускает браузер, не создаёт контексты и вкладки, не держит очередей и семафоров; это
проверяет `tests/test_layers.py` разбором кода всех модулей пакета.

Всё, что умеет не каждый драйвер, объявляется **возможностью** (`Capability`), а не
добавляется в протокол: иначе половина адаптеров держала бы заглушки. Что нужно операции,
раннер собирает из `requires=`, признаков и маркеров карты и сверяет с профилем драйвера
**до первого действия** — одним `CapabilityMismatchError` ядра со всеми осями разом.

## 4. Почему форма именно такая

Форму выбирали не спором, а тремя спайками с замерами типизатора. Одна и та же операция
записывалась тремя способами; различалась только форма объявления.

| | A: дескрипторы | **B: `Annotated`** | C: `__init_subclass__` |
|---|---|---|---|
| Опечатка в имени элемента | ошибка | **ошибка** | проходит молча |
| Операция неизменяема | нет | **да** | нет |
| Одну операцию можно гонять в двух вкладках сразу | нет | **да** | нет |

Победила **B**. Решающим оказался не синтаксис, а то, что A и C кладут драйвер в
экземпляр операции: два одновременных выполнения перетирают его друг другу. Это не
рассуждение — тест `test_same_operation_serves_two_tabs_at_once` показывает это на
фейковом драйвере, который уступает управление, как настоящий.

Второй спайк разбирался с переходами, третий — с отказами. Дословные выводы типизатора
и разобранные варианты — в `decisions.md`. После спайков форма ещё раз поменялась — уже не
механика, а словарь: одна спека вместо россыпи dunder-атрибутов, роутер и клиент вместо
`execute(driver)`, имена без коллизий с ядром (`REUSE.md`, `PLAN.md`).

## 5. Отказы: у них две природы, и путать их нельзя

| Природа | Чем объявляется | Где |
|---|---|---|
| Страница показала баннер, увела на форму входа | `Failure(when=<признак>, exception=<класс или фабрика>)` | `errors = ...` у роутера и `errors=` в спеке; частные правила выше общих |
| API ответил `409`, `403`, `5xx` | `Responses(success=..., errors=...)` из `eazy-sdk` | поле карты `ApiResponse(url, sdk_cases(...))` |

Второе — и есть главный выигрыш от соседства с HTTP-библиотекой. Ответ браузера это
обычный HTTP-ответ, поэтому разбирает его **то же самое объявление**, что и в HTTP-SDK:
выбор случая по статусу и медиа-типу, разбор модели, условия по телу, свои исключения,
`UnexpectedResponseError` для ответа, не подошедшего ни под один случай. Своего языка
для этого не заведено.

Правила отказов проверяются **первыми в том же цикле опроса**, что и исходы. Иначе
страница, показавшая «неверный пароль», сначала выждала бы общий таймаут и вернулась бы
«ничем не подтверждено»: отказ выглядел бы неопределённостью. Невыполненное условие
готовности тоже сначала спрашивает правила: кнопки нет, потому что портал увёл на вход, —
это истёкшая сессия, а не «страница не готова».

Отдельно — **помехи**: `Handle(when=..., do=...)` в `handlers=`. Баннер согласия
перекрывает и признак отказа, и признак исхода, поэтому помеху убирают ещё **до
действия** — клик сквозь баннер ушёл бы в баннер — и снова ищут в цикле ожидания.
`once=True` считается на всю операцию и не даёт зациклиться на том, что убрать не удалось.

## 6. Где живёт форма, которой ещё нет на странице

Вопрос, с которого начинается любой настоящий SDK, и ответы, которые нельзя путать:

| | Что это | Как объявляется |
|---|---|---|
| Панель фильтров | **есть в DOM всегда** | подкарта: `region(FilterPanel, root=css("form.filters"))` |
| Строки таблицы | **много однотипных узлов** | коллекция: `Annotated[Elements, each(css("table tr"))]` |
| Диалог создания компании | **появляется по клику** | отдельная карта **и отдельное состояние** |

Форма создания компании — **не поле карты списка**. В карте списка только кнопка. Связь
даёт переход: `OpenCreateCompany` возвращает `CreateCompanyDialog`, и только у него есть
`submit`. Причина не в эстетике: у диалога **своё условие готовности**, и будь форма
полем карты списка, её локаторы существовали бы до клика — опечатка в селекторе всплыла
бы не при открытии, а когда-нибудь потом.

## 7. Транспорт не протекает в карты

Драйвер — низкоуровневая вещь, и в карту элементов он не попадает. Всё, что операции нужно
от драйвера сверх минимума, **объявляется**:

* **сеть** — ответ страницы полем карты `ApiResponse(...)`, признак `response.arrived(...)`
  и `requires=(Capability.network,)`; одно без другого — D-B-04;
* **переход как событие** — признак `navigated()` и `requires=(Capability.navigation_events,)`;
* **редактор форматированного текста** — поле `rich(css(...))` и
  `requires=(Capability.rich_text,)`;
* **состояние сессии** — вход `BrowserLogin` у клиента, руками — `require_state(driver)`;
* **запрос из страницы** — `BrowserHandler` для HTTP-клиента.

Карта элементов при этом остаётся картой элементов. Это исправление конкретных ошибок
ранних версий: в карте формы входа лежало поле `session: Annotated[Driver, CurrentDriver()]`,
а сеть операция получала наследованием от особой базы — и то и другое смешивало логику с
транспортом.

## 8. Что даёт соседство с `eazy-sdk`

Библиотека переехала в этот репозиторий не ради порядка в файлах, а ради двух связей,
каждая из которых проверена на живом сервисе (почта GMX, `gmx-sdk` — отдельный
репозиторий, намеренно внешний потребитель).

### HTTP → браузер: жизненный цикл сессии и общее хранилище

Вход стоит дорого — капча, антибот, второй фактор. Его результат нужно где-то держать и
обновлять, и у `eazy-sdk` для этого уже есть всё: транспортно-нейтральный
`SessionLifecycle`, аккаунты, сессии, история событий, ограничения со сроком, пул с
ротацией. Браузеру нужно **то же самое**:

```python
MAIL_LOGIN = BrowserLogin(            # одно на сайт, общее для всех аккаунтов
    service=MailLogin(),               # операции страницы входа → export_state()
    cookies=("sid",),
    expired=(SessionExpiredError,),    # после такого отказа — вход заново и повтор
)
mail = MAIL_LOGIN.session(credentials, store=sessions.store(account))  # один на контекст
client = AsyncBrowserClient(driver, base_url="https://mail.example", session=mail)
```

Объявление входа — знание сайта: как войти и какой отказ значит «сессия кончилась».
`BrowserSession` — жизненный цикл сессии **одного контекста** браузера на
`SessionLifecycle` ядра: один вход на все вкладки контекста, куки в контекст — только
когда их там нет. Сколько контекстов, вкладок и с каким `storage_state` — решает код
вызывающего или пул браузеров (`LAYERS.md`).

Проверено делом: отказ антибота (`403 blocked`) перестал быть строкой в логе и стал
**заморозкой ящика на час**, которую видит пул, — следующий запуск сам берёт другой
ящик вместо того, чтобы упорствовать с тем же. Ни одного браузерного понятия в общий
слой добавлять не пришлось.

### Браузер → HTTP: сессия и транспорт с пройденным входом

Сессию, полученную браузером, HTTP-клиент берёт мостом ядра `BridgedSessionAdopter`:

```python
auth = await browser_cookie_auth(await mail.state(client), MAIL_SESSION, "sid")
folders = await MailApi(http, identity=Identity(auth=(auth,))).folders()
```

Обратная сторона — запрос, выполненный **изнутри страницы**. Он уходит её куками, её TLS,
её источником и её антиботом — для сервиса это обращение его же приложения:

```python
handler = BrowserHandler(driver, frames=('iframe[name="mail"]',))
async with AsyncClient(base_url="https://maillist.example", handler=handler) as client:
    page = await MailApi(client).page(offset=50)
```

`BrowserHandler` — обычный обработчик `zapros`, он подставляется в `AsyncClient` наравне
с httpx и curl_cffi. Пятидесятое письмо достаётся без сорока девяти нажатий «дальше».

**Объявление ответа при этом одно на оба транспорта**: те же кортежи `success=`/`errors=`
разбирают и перехваченный ответ, и ответ на прямой запрос. Контракт сервиса описан один
раз, а чем его выполнить — решается при сборке клиента. А роутеры обоих транспортов
живут в одном `AsyncRoot`: `sdk.api.create(...)` уходит запросом, `sdk.portal.open_create_company()`
— кликом.

Чего браузер не умеет — порядок, регистр и повторы заголовков, ручной `Cookie`,
остановку редиректов — объявлено в `HandlerProfile`, а не выясняется посреди сценария.

## 9. Чего это стоило узнать

Слияние работает как проверка архитектуры: переиспользовать компонент из чужого слоя
получается только при низкой связанности, поэтому каждое место, где не получилось, —
найденный дефект. Полный список — `MERGE.md` §6 и `CORE_DEBT.md`; самое полезное:

* **модель куки в `eazy-sdk` была две, и обе неполные** — `SessionData.cookies` это
  `dict[str, str]`, браузеру такого мало, а `HttpCookieSession` со всеми атрибутами уже
  существует рядом;
* **`zapros` подставляет свой `User-Agent`**, и на браузерном транспорте он бы **дошёл**
  до сервиса: `fetch` разрешает его переопределять. Транспорт, взятый ради
  неотличимости от браузера, представился бы `python-zapros/0.16.0`;
* **`credentials: 'include'` ломает то, что работает без него** — сервис, авторизующий
  токеном, не выдаёт `Access-Control-Allow-Credentials`. Замерено: `include` →
  `Failed to fetch`, `same-origin` и `omit` → `200`;
* **куки — не единственная аутентификация**: GMX подписывает запросы `Authorization`,
  который знает только его SPA. SDK его не выдумывает, а подсматривает в запросах самой
  страницы;
* **корень SDK не принимал роутер другого транспорта** — появился протокол ядра
  `_ComposesItself`; а **cookie-привязки, принимающей сессию со стороны, в ядре нет** —
  мост из браузера отдаёт статический `Auth`.

## 10. Долг и открытое

* **Долг ядра**, найденный плагином, — `CORE_DEBT.md`: задачи для ядра, не для плагина.
* **Линт.** Строгий набор (25+ правил) включён на весь репозиторий; то, что старый код
  ещё не проходит, вынесено в `per-file-ignores` как явный список долга. Он должен только
  сокращаться.
* **Сложность.** `complexipy` считает пока только этот плагин. По `eazy_sdk` порог 15
  нарушают 62 функции.
* **Второй адаптер.** Пока драйвер один, «общее» из браузерной части вытаскивать рано:
  selenium или camoufox покажут, что там действительно общее.
* **Улики при отказе** (скриншот, HTML) сознательно не сделаны: нужны включаемыми, это
  отдельная задача.
* **Настоящий scoping.** `region` и `scope=` скоупятся склейкой CSS; для shadow DOM нужен
  поиск внутри элемента в протоколе драйвера.
* **Полный прогон workspace** в этапах B4 и B5 на машине разработки не завершился:
  тесты ядра на localhost зависали в loopback. Прогон нужно повторить на исправной машине.
* **Этап 3 исходного плана — стайл-чекер** — не начат.

Остальные открытые вопросы пронумерованы в `DESIGN.md` §6.

## 11. Как это проверять

```bash
uv sync --all-groups
uv run ruff check                        # линт, общий строгий набор
uv run mypy                              # типы, strict
uv run lint-imports                      # четыре архитектурных контракта
uv run complexipy --plain --failed       # когнитивная сложность
uv run pytest -q plugins/browser/tests   # только этот плагин
```

Интеграционные тесты поднимают настоящий Chromium; без браузера они пропускаются, а не
падают. Установить: `uv run playwright install chromium`.

Отдельно — пробник типизатора: он содержит намеренные ошибки и потому исключён из `mypy`
и `ruff`. Важен не факт падения, а какие строки типизатор назовёт, а какие пропустит:

```bash
uv run basedpyright plugins/browser/probe/typing_probe.py
```

Страницы сайта документации проверяются так же, как остальные страницы ядра:

```bash
uv run python scripts/docs_freshness.py check
uv run --group docs python docs-site/scripts/validate_docs.py
uv run --group docs sphinx-build -W --keep-going -b dirhtml -c docs-site docs-site/src/content/docs docs-site/_build/html
```
