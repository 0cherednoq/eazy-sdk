## 0. Как исполнять этот план автономно

1. **Возобновление.** Первое действие новой сессии: прочитать таблицу §9.1, журнал §9.2 и строку
   фазы 59 в `STATUS.md`, затем `git log --oneline` ветки `feat/phase59`. Первый шаг со статусом,
   отличным от `done`, — текущий. Шаг в статусе `in progress` продолжается с того, что записано в
   его строке «Что осталось».
2. **Порядок шагов**: 59.0 → 59.1 → … → 59.9. Шаги 59.1–59.8 друг от друга не зависят, кроме
   одной связи: 59.4 меняет чтение источников поля, а 59.2 — чтение объявления модели, оба в
   `eazy_sdk/response/`; делать их в указанном порядке, не параллельно. Если шаг заблокирован,
   следующий независимый можно начинать, записав это в §9.2.
3. **Каждый шаг — отдельный коммит** `Phase 59.N: <что сделано>` с тестами внутри, в ветке
   `feat/phase59`. Тем же коммитом обновляются строка шага в §9.1, журнал §9.2 и строка фазы в
   `STATUS.md`: прогресс не живёт вне дерева. Файлы каталога `docs/` добавляются через
   `git add -f`, он в `.gitignore`.
4. **Незавершённый шаг сохраняется.** Если сессия прерывается посреди шага, в §9.1 ставится
   `in progress` с перечнем сделанного и оставшегося, изменения коммитятся как
   `Phase 59.N (wip): <что сделано>`. Следующая сессия доводит шаг и закрывает его обычным
   коммитом.
5. **Один способ.** Новая форма не становится вторым путём к тому же: где она заменяет старую
   целиком, старая удаляется в том же шаге (в этой фазе таких мест нет, см. §2, I1). Алиасов и
   обёрток нет.
6. **Проверки — при объявлении.** Всё, что видно по классам, проверяется при импорте или при
   первой компиляции операции, до запроса. Коды диагностик — `D-59-NN`, перечень в §4.
7. **Имена — решения по умолчанию.** Имена в §3 выбраны планом. Владелец может заменить имя до
   начала шага; после коммита шага имя меняется только отдельным решением в §10.
8. **Остановка.** Останавливаться, если проба 59.0 опровергает допущение плана или если шаг
   требует сломать существующее объявление. Остановка записывается в §9.1 статусом `blocked` с
   вопросом к владельцу.

Гейты каждого шага: сфокусированные тесты шага, затем `uv run pytest -q`, `uv run mypy`,
`uv run ruff check`. Гейты выпуска — в 59.9.

## 1. Что не так (по одному абзацу на пробел)

**Пробел 3.** `Const` утверждает «поле равно значению». Конверт ARMGS различает успех и отказ
как «`status` равен 200» и «`status` не равен 200», а отказ токена — как «`status` один из 401,
403». Ни то, ни другое тегом не записать, и автор уходит в `accept=lambda` или в выбор класса
внутри фабрики исключения. Критерий перестаёт быть виден в диагностике и не проверяется при
импорте.

**Пробел 2.** `_read_declaration` (`eazy_sdk/response/markers.py`) берёт аннотации через
`typing.get_type_hints`. У параметризованной pydantic-модели подстановка лежит в
`model_fields`, поэтому `Payload[T]` читается как `T`, и операция падает при первой компиляции.
Обобщённый конверт `Ok[T]` — естественная запись, и она недоступна.

**Пробел 4.** `decide_response` (`eazy_sdk/clients/_decisions.py`) переходит к обновлению сессии
только при HTTP 401. Сервис, который сообщает об отказе токена внутри HTTP 200, обновления не
получает: объявленный случай ошибки поднимается вызывающему, хотя сессия обновляема.

**Пробел 7.** Поле ответа имеет ровно один источник (`source_of` в
`eazy_sdk/response/sources.py` отклоняет два). Значение, которое сайт кладёт то в страницу, то в
cookie, требует двух необязательных полей и свойства. Модель из необязательных полей подходит
любой странице, и автор добавляет условие-заглушку, чтобы пройти проверку различимости.

**Пробел 6.** `Inject` принимает константу или провайдер с `DependencyContext`, а в контексте
нет адреса сервиса. `Origin` и `Referer` формы входа — это адрес другого роутера того же корня;
сегодня это константа уровня модуля, которая расходится с `bind(..., base_url=...)`.

**Пробел 5.** Адрес, пришедший в ответе (`Attachment.download_url`), нельзя передать аргументом
операции. Переадресация объявления на готовый адрес в ядре есть (`_at_url` в `eazy_sdk/api.py`,
её использует `Pages.next_url`), публичного входа нет.

**Пробел 8.** Узнать текущую сессию и cookies пользователя можно только через хранилище, зная
формат ключа (`session:{identity or 'client'}`), и только после защищённого вызова, который
вызвал вход.

**Пробел 9.** `Failure` браузерной линии принимает класс или фабрику `async (page) -> Exception`.
Подробности отказа, которые на странице лежат списком элементов, фабрика читает руками, хотя для
исходов то же самое описывается картой страницы.

## 2. Инварианты фазы

- **I1. Ничего не удаляется.** Все восемь изменений добавляют форму. `Const`, `accept=`,
  `unwrap=`, `Inject` с константой, `Failure` с фабрикой остаются и ведут себя как в `0.2.0a11`.
- **I2. Критерий остаётся утверждением о теле.** Новые теги (59.1) ранжируются как `Const` и
  читаются одинаково на `success=` и `errors=`.
- **I3. Обновление сессии не меняет бюджет.** 59.3 расходует тот же `Resilience.auth_retries` и
  подчиняется тому же правилу идемпотентности, что и ветка HTTP 401.
- **I4. Секрет не уходит на чужой адрес.** 59.6: размещения сессии и подпись применяются к
  запросу по абсолютному адресу только в пределах объявленных хостов; иначе запрос не уходит.
- **I5. Корень SDK не получает новых имён.** 59.7 добавляет функции, а не методы корня: имена
  атрибутов корня принадлежат роутерам автора.
- **I6. Бюджет экспорта корня `eazy_sdk` не растёт.** Новые имена публикуются из
  `eazy_sdk.response`, `eazy_sdk.request.markers`, `eazy_sdk.auth`, `eazy_sdk.cookies`,
  `eazy_sdk_browser`.

## 3. Целевой API

### 3.1. Теги `OneOf` и `Not` (пробел 3, шаг 59.1)

```python
from eazy_sdk.response import Const, Not, OneOf

class EnvelopeRefused(BaseModel):
    status: Annotated[int, Not(200)]
    body: Any = None

class TokenRefused(BaseModel):
    status: Annotated[int, OneOf(401, 403)]
    body: Any = None
```

- `OneOf(*values)` — JSON Schema `enum`; `Not(value)` — `not: {const: value}`. Значения те же,
  что у `Const`: строка, число, булево, `None`; сравнение вместе с типом.
- Многозначный `Literal[401, 403]` читается как `OneOf` (сегодня не читается никак).
- В диагностике: `<status in (401, 403)>`, `<status != 200>`.
- Ранжирование не меняется: тег есть критерий. Две модели, обе подошедшие (`Not(200)` и
  `OneOf(401, 403)` на статусе 401), остаются двусмысленностью; порядок случаев — вне фазы (§8).
  Для ARMGS это решается объявлением: `Not(200)` заменяется на то, что реально различимо, либо
  отказ токена объявляется на операции, а общий отказ — в `fallback`. Какой вариант — записать в
  §9.2 при приёмке.

### 3.2. `Payload[T]` в обобщённой модели (пробел 2, шаг 59.2)

```python
class Ok[T](BaseModel):
    status: Annotated[int, Const(200)]
    body: Payload[T]

class GetAccount(HttpOperation[Account]):
    __http__ = Http.get("/api/v1/user/short", success={200: Ok[Account]})
```

- `declaration_of` читает параметризованную модель с подстановкой: pydantic — по
  `__pydantic_generic_metadata__`, dataclass и msgspec — по `get_origin`/`get_args` псевдонима и
  параметрам класса (PEP 695 и `Generic[T]`).
- Вложенные формы подставляются целиком: `Payload[list[T]]`, `Payload[T | None]`.
- Непараметризованная `Ok` с `Payload[T]` в `success=` — ошибка объявления (`D-59-03`).
- Допущение, которое проверяет 59.0: реестр моделей загружает параметризованный dataclass и
  msgspec-псевдоним. Если нет — объём шага для них записывается в §9.2 до начала работы.

### 3.3. Обновление сессии по объявленному отказу (пробел 4, шаг 59.3)

```python
class TokenRejected(ApiError[TokenRefused]):
    reauth = True                                  # короткая форма

Error(200, Json(TokenRefused), exception=TokenRejected, reauth=True)   # полная форма
```

- Ответ, который выбрал случай с `reauth`, при обновляемой сессии и остатке `auth_retries` ведёт
  к `AuthRefreshTransition` — той же, что HTTP 401: текущая ревизия сессии признаётся негодной,
  вызывается `refresh` (или `acquire`), запрос готовится и подписывается заново.
- Бюджет исчерпан или сессия не обновляема — поднимается объявленное исключение, как сегодня.
- Случай с `reauth` на операции без обновляемой авторизации (`security=None`, статическая
  схема) — ошибка объявления (`D-59-04`).
- `ResponseDecisionInput.outcome` уже несёт выбранный случай; новая ветка стоит рядом с веткой
  401 и после сигналов защиты.

### 3.4. Запасной источник поля (пробел 7, шаг 59.4)

```python
class LoginPage(BaseModel):
    csrf: Annotated[str, Regex(r'"csrf":"([^"]+)"') | FromCookie("act")]
```

- `A | B` на маркерах источников даёт `FirstOf(A, B)`: источники пробуются слева направо, берётся
  первое найденное значение. Участвуют источники ядра (`FromHeader`, `FromCookie`,
  `Location.query`) и селекторы документа (`CSS`, `XPath`, `Regex` из `eazy_sdk_html`).
- Обязательное поле с `FirstOf`, в котором ничего не нашлось: если среди источников есть
  `Location`/`Location.query` — «это другой ответ» (`NoMatch`), иначе ошибка разбора, как у
  одиночного источника.
- Обязательное поле с `FirstOf` считается обязательным селектором для проверки различимости
  модели документа: заглушка `when=match.status.is_(200)` становится не нужна.
- `Location(...)`-шаблон в `FirstOf` не участвует: он критерий, а не только источник
  (`D-59-05`).

### 3.5. Адрес сервиса как источник `Inject` (пробел 6, шаг 59.5)

```python target
from eazy_sdk import Inject
from eazy_sdk.dependencies import service_url

inject=(
    Inject(markers.Header("Origin"), service_url(LoginPagesApi)),
    Inject(markers.Header("Referer"), service_url(LoginPagesApi, "/")),
    Inject(markers.Query("page"), service_url(MailPagesApi, "/inbox")),
)
```

- `service_url(Router | None = None, path="")` — источник, который при подготовке запроса отдаёт
  адрес, к которому привязан роутер в этом корне (`bind(Router, base_url=...)`, иначе `base_url`
  клиента); без роутера — адрес сервиса самой операции.
- Роутер, которого нет в корне, — ошибка при первой компиляции операции (`D-59-06`).
- `DependencyContext` получает доступ к адресам корня; для прежних провайдеров ничего не
  меняется.
- Тело с `BodyProjection`: значение для поля формы (`page` у ARMGS) должно дойти до проекции.
  Проба 59.0 выясняет, получает ли проекция значения `Inject`; если нет, шаг добавляет это и
  записывает форму в §9.2.

### 3.6. Абсолютный адрес аргументом вызова (пробел 5, шаг 59.6)

```python
@dataclass(frozen=True, slots=True, kw_only=True)
class DownloadAttachment(HttpOperation[bytes]):
    __http__ = Http.get(Url(hosts=("*.armgs.team",)), security=None, success={200: Bytes()})

    url: Url[str]
```

- Операция объявляет вместо пути `Url(hosts=...)` и ровно одно поле `Url[str]`. Запрос уходит по
  адресу из поля; `Path`-поля запрещены (`D-59-07`), `Query`-поля добавляются к адресу.
- `hosts` обязателен: шаблоны как у `Location(host=...)`. Адрес вне списка — ошибка до отправки
  (I4), а не запрос без авторизации. Относительный адрес резолвится против адреса сервиса.
- Cookies из jar выбираются по фактическому адресу (так уже работает). Размещения сессии и
  подпись применяются по обычным правилам операции; чужой хост исключён списком `hosts`.
- Реализация — существующая переадресация объявления (`_at_url`), вынесенная из пагинации в
  общий путь; `Pages.next_url` переходит на него же без изменения поведения.

### 3.7. Текущая сессия и cookies пользователя (пробел 8, шаг 59.7)

```python target
from eazy_sdk.auth import current_session, ensure_session
from eazy_sdk.cookies import cookies_of

session = await ensure_session(sdk)          # войти, если ещё не вошли; вернуть сессию
session = await current_session(sdk)         # что есть сейчас, без входа; None, если нет
cookies = cookies_of(sdk)                    # снимок jar'а пользователя, CookieState
```

- Функции принимают корень или роутер, которому передан `identity=`. Схема выбирается
  аргументом `scheme=`; если у корня одна сессионная схема, аргумент не нужен, если несколько и
  он не задан — ошибка с перечнем схем.
- `ensure_session` идёт тем же путём, что первый защищённый вызов (singleflight, сохранение
  cookies рядом с сессией), и не шлёт прикладного запроса.
- Формат `SessionKey` остаётся внутренним.

### 3.8. Отказ страницы с картой элементов (пробел 9, шаг 59.8)

```python
class Problem:
    reason: Annotated[str, text(css("b"))]
    address: Annotated[str, text(css("br + *"))]

class RejectedDialog:
    problems: Annotated[list[Problem], each(css('p[data-test-id^="error:"]'))]

def _rejected(dialog: RejectedDialog) -> RecipientRejected: ...

Failure(when=text.contains(_INVALID_CAPTION), reads=RejectedDialog, exception=_rejected)
```

- `reads=` — карта страницы, собираемая тем же `build_content`, что и у исходов, без ожидания:
  отказ уже наблюдается. Фабрика получает значения, а не `Observation`; может быть синхронной.
- `reads=` без фабрики или с фабрикой, чей параметр не эта карта, — ошибка объявления
  (`D-B-NN`, номер по реестру браузерной линии).
- Допущение для 59.0: карта умеет читать **значения** (текст) списка элементов. Если сегодня
  карта отдаёт только элементы для действий, шаг сначала добавляет читающие маркеры; объём
  записывается в §9.2. Точные селекторы примера выше — иллюстрация, не контракт.

## 5. Шаги

Для каждого шага: что меняется, тесты, критерий выхода. Тесты ядра —
`tests/unit/test_phase59_<тема>.py`, браузерной линии — `plugins/browser/tests/`.

### 59.0. Пробы (кода не меняют)

Каждая проба — короткий скрипт или тест, результат одной строкой в §9.2.

1. `Ok[Account]` на pydantic, dataclass (PEP 695) и msgspec: что доходит до `declaration_of`,
   загружает ли реестр моделей параметризованный тип.
2. Где исполнитель собирает `ResponseDecisionInput` и доступен ли там выбранный `Error`-случай
   (`executor.py`, рядом с `auth_refreshable`).
3. Получает ли `BodyProjection.using` значения `Inject` (есть `stage.injected` для `requires=`).
4. Что `_at_url` делает с размещениями сессии и подписью на чужом хосте.
5. Умеет ли карта страницы браузерной линии читать текст списка элементов (`each`, `text`).
6. Как `HtmlExtractor` сообщает «селектор ничего не нашёл» для необязательного поля — место, где
   встанет `FirstOf`.

Критерий выхода: шесть записей в §9.2; допущения §3 подтверждены или шаги уточнены.

### 59.1. `OneOf` и `Not`

- `eazy_sdk/response/markers.py`: два маркера; `Tag` получает вид сравнения (равно, один из, не
  равно) и подпись для диагностики; `_read_declaration` читает их и многозначный `Literal`;
  `_refuse_impossible_constant` проверяет каждое значение.
- `eazy_sdk/response/__init__.py`: экспорт `OneOf`, `Not`.
- Генератор OpenAPI: `enum` с несколькими значениями и `not: {const}` выпускаются этими тегами,
  если генератор уже выпускает `Const` (проверить; если нет — вне шага, записать в §9.2).
- Тесты: совпадение и несовпадение с учётом типа (`1` против `True`), отсутствующее поле,
  ранжирование против случая без критерия, D-59-01, D-59-02, подписи в
  `AmbiguousResponseError`.

Критерий выхода: конверт вида §3.1 различает успех, отказ и отказ токена без `accept=`.

### 9.3. Отклонения от плана

- **59.1: многозначный `Literal` не читается как `OneOf`.** План (§3.1) это обещал. Существующий
  тест `test_a_one_value_literal_counts_as_the_same_statement` фиксирует обратное, и причина
  верная: обычное поле-перечисление стало бы критерием и изменило бы ранжирование объявлений,
  написанных под `0.2.0a11` (инвариант I1). Тег на несколько значений пишется только явно.
- **59.2: только pydantic.** Параметризованные dataclass и msgspec реестр моделей не загружает
  независимо от `Payload` (проба 1). Поддержка обобщённых моделей в адаптерах — отдельная работа.
- **59.1–59.5 одним коммитом.** Шаги писались подряд и делят `eazy_sdk/response/__init__.py`;
  правило «шаг — коммит» нарушено, прогресс по шагам записан раздельно.
- **59.5: D-59-06 — при подготовке запроса**, не при компиляции операции (см. журнал).
