Операция объявляется классом. Его поля — это поля запроса, `__http__` — всё остальное, что
операция объявляет о себе, а `op(...)` публикует её на роутере. Публичной сигнатурой SDK
становится конструктор класса, поэтому IDE и type checker видят имена полей, их типы и значения
по умолчанию до первого запуска.

Эта страница — единственное место в документации, где рядом показаны обе формы объявления:
класс и декоратор. Во всех остальных руководствах операции объявлены классами.

## Класс

```python
from dataclasses import dataclass

from eazy_sdk import UNSET, Http, HttpOperation, JsonField, Omittable, Path, Query, SyncApi, op

@dataclass(frozen=True, slots=True, kw_only=True)
class CreateOrder(HttpOperation[Order]):
    __http__ = Http.post("/customers/{customer_id}/orders", success={201: Order})

    customer_id: Path[str]
    item: JsonField[str]
    quantity: JsonField[int] = 1
    dry_run: Query[bool] = False
    comment: JsonField[Omittable[str]] = UNSET

class OrdersApi(SyncApi):
    create_order = op(CreateOrder)
```

Четыре требования к классу, и других нет:

| Требование | Почему |
|---|---|
| `HttpOperation[T]` в базах | `T` — тип успешного ответа и тип, который вернёт вызов |
| `__http__ = Http.<verb>(...)` | метод, путь и весь контракт операции |
| класс **frozen** | запрос является значением: его копируют и отправляют повторно |
| поля keyword-only | HTTP-параметры не имеют осмысленного порядка |

Класс может быть dataclass, Pydantic-моделью или msgspec-структурой — любой, который читает
настроенный `ModelAdapterRegistry`:

```python
from pydantic import BaseModel, ConfigDict

class GetPost(BaseModel, HttpOperation[BlogPost]):
    model_config = ConfigDict(frozen=True, serialize_by_alias=True)
    __http__ = Http.get("/posts/{post_id}")

    post_id: Path[int]
```

`ClassVar`-атрибуты полями запроса не становятся, поэтому `__http__` и любые константы класса
на провод не уходят.

## Что даёт класс

```python
from dataclasses import field
from uuid import uuid4

@dataclass(frozen=True, slots=True, kw_only=True)
class Ping(HttpOperation[Pong]):
    __http__ = Http.get("/ping")

    trace_id: Annotated[str, markers.Header("X-Trace")] = field(
        default_factory=lambda: uuid4().hex
    )
```

- **Значения по умолчанию и `default_factory`** — обычные Python-механизмы; фабрика вызывается
  на каждое построение запроса.
- **Запрос как значение**: `request()`, `evolve()`, `send()` (см. {doc}`Запрос как значение
  </guides/requests/values>`).
- **Источник проекции**: `BodyProjection` без `source=` получает само значение операции
  (см. {doc}`Представление запроса </guides/requests/representation>`).
- **Наследование**: общий набор полей выносится в базовый класс операции обычным наследованием
  dataclass — подкласс переобъявляет `__http__` и добавляет свои поля.
- **Повторное использование**: один класс можно опубликовать на нескольких роутерах;
  `operation_id` по умолчанию берётся от имени класса, а не от имени атрибута.

```python
@dataclass(frozen=True, slots=True, kw_only=True)
class ListPage(HttpOperation[Page]):
    __http__ = Http.get("/items")

    page: Query[int] = 1
    per_page: Query[int] = 20

@dataclass(frozen=True, slots=True, kw_only=True)
class ListArchivedPage(ListPage):
    __http__ = Http.get("/items/archived")

    since: Query[str]
```

## Декоратор как короткая форма

Тот же метод можно объявить декоратором. Он синтезирует ровно такой же frozen-класс — класс
доступен как `OrdersApi.create_order.Operation`:

```python
from typing import Annotated

from eazy_sdk import UNSET, Omittable, SyncApi, api
from eazy_sdk.request import markers

class OrdersApi(SyncApi):
    @api.post("/customers/{customer_id}/orders", success={201: Order})
    def create_order(
        self,
        *,
        customer_id: Annotated[str, markers.Path()],
        item: Annotated[str, markers.JsonField()],
        quantity: Annotated[int, markers.JsonField()] = 1,
        dry_run: Annotated[bool, markers.Query()] = False,
        comment: Annotated[Omittable[str], markers.JsonField()] = UNSET,
    ) -> Order:
        raise NotImplementedError
```

Правила декоратора:

- аннотация возвращаемого типа обязательна — она называет успешный случай так же, как
  `HttpOperation[T]`;
- тело не выполняется; пишите `raise NotImplementedError`, потому что `...` strict mypy считает
  ошибкой `empty-body`;
- параметры keyword-only, как и поля класса;
- `Http.get` и `api.get` — одна и та же функция с одним набором ключевых слов, включая
  `Http.request(method, path)` / `api.request(method, path)` для нестандартного HTTP-глагола.

## Что выбрать

| | Класс + `op(...)` | Декоратор |
|---|---|---|
| Значения по умолчанию | обычные defaults и `default_factory` | обычные defaults; `default_factory` недоступен |
| Запрос как значение | `request()`/`evolve()`/`send()` | только прямой вызов |
| `options` одного вызова | `send(request, options=...)` | параметр вызова: `create_order(..., options=...)` |
| Источник проекции | сам класс операции | синтезированный класс, `.Operation` |
| Наследование полей | обычное наследование класса | повтор в сигнатуре |
| Объём объявления | класс + строка `op(...)` | один метод |

Декоратор остаётся удобным для короткой ручки без тела и без общих полей. Всё остальное —
пагинация, отложенная отправка, общий набор полей у семейства операций, проекция в приватную
wire-схему — короче и точнее выражается классом.

Обе формы проходят один и тот же путь исполнения: декоратор не является отдельным механизмом, он
собирает класс и публикует его тем же дескриптором.
