Реализуйте limiter и передайте его в `ClientConfig`. Limiter резервирует право на фактическую
отправку, а не на logical API call.

```python
from eazy_sdk import Client, ClientConfig
from eazy_sdk.ratelimit_runtime import RateLimitDecision

class ApiLimiter:
    async def reserve(self, context):
        delay = await bucket.reserve(context.authority)
        return RateLimitDecision(delay=delay)

client = Client(
    base_url=base_url,
    handler=handler,
    config=ClientConfig(rate_limiter=ApiLimiter()),
)
```

Conditional challenge replay получает новую reservation. Single-flight solve и managed
protection cache сами по себе reservation не потребляют: limiter вызывается только перед
фактическим transport send.

Limiter применяется перед каждой отправкой, включая retry и redirect.

`context.authority` позволяет разделить buckets по upstream. Limiter может учитывать operation,
attempt и deadline из context, но не должен отправлять HTTP request самостоятельно.

Если reservation возвращает delay, executor ждёт с поддержкой cancellation и общего timeout.
Retry после `429` создаёт новую reservation. Nested login, protection acquire и verify также
проходят limiter, потому что являются обычными scoped API-методами.
