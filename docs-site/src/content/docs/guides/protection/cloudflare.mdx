Preset распознаёт definitive challenge по `cf-mitigated: challenge` и HTML content type. Status
сам по себе недостаточен.

```python target
from datetime import UTC, datetime, timedelta

from eazy_sdk import ClientConfig
from eazy_sdk.protection import ChallengeSolverBindings, bind_challenge_solver
from eazy_sdk_presets import cloudflare, host

class CloudflareSolver:
    async def solve(self, challenge, context):
        return cloudflare.CloudflareClearance(
            cookies=(
                cloudflare.SecretCookie("cf_clearance", "clearance-value"),
                cloudflare.SecretCookie("__cf_bm", "managed-value"),
            ),
            expires_at=datetime.now(UTC) + timedelta(minutes=30),
        )

policy = cloudflare.challenge_pages(scope=host("api.example.test"))
config = ClientConfig(
    challenge_policies=(policy,),
    challenge_solvers=ChallengeSolverBindings(
        bind_challenge_solver(policy.solver, CloudflareSolver()),
    ),
)
```

Все элементы `CloudflareClearance.cookies` применяются одним private batch. По умолчанию state
живёт `until_rejected` в network identity scope. Новый proxy/User-Agent не получает старый
clearance; повторный challenge инвалидирует применённый набор перед replay.
