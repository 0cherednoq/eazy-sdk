Protection отделяет требование операции от реализации challenge flow. Декоратор говорит, какой
typed result обязателен. `ClientConfig` определяет, как получить этот result и какой solver
использовать.

```bash
uv add eazy-sdk-presets
```

## Обязательная CAPTCHA перед login

Публичная request-модель содержит только данные caller-а. Managed поля находятся в приватной
wire-модели и заполняются одним protection result атомарно.

```python
from typing import Annotated, TypedDict, Unpack, cast

from pydantic import BaseModel

from eazy_sdk import AsyncApi, ClientConfig, api
from eazy_sdk.protection import (
    FromProtection,
    ProtectionRequirement,
    SolverBindings,
    bind_solver,
    protection_flow,
)
from eazy_sdk.request import BodyProjection, JsonBody

class LoginRequest(TypedDict):
    email: str
    password: str

class CaptchaResult(BaseModel):
    challenge: str
    token: str

LOGIN_PROTECTION = ProtectionRequirement[CaptchaResult]("login-protection")

class _LoginWireBody(LoginRequest):
    captcha_challenge: Annotated[
        str,
        FromProtection(LOGIN_PROTECTION, "challenge"),
    ]
    captcha_token: Annotated[
        str,
        FromProtection(LOGIN_PROTECTION, "token"),
    ]

def login_to_wire(source: LoginRequest) -> _LoginWireBody:
    # Reserved protection fields are deliberately absent until the attempt writer runs.
    return cast(_LoginWireBody, dict(source))

LOGIN_BODY = BodyProjection(
    source=LoginRequest,
    target=_LoginWireBody,
    using=login_to_wire,
    encoding=JsonBody(),
)

class AsyncAuthApi(AsyncApi):
    @api.post(
        "/auth/login",
        operation_id="login",
        responses=LOGIN_RESPONSES,
        protections=(LOGIN_PROTECTION,),
        body=LOGIN_BODY,
    )
    async def login(self, **request: Unpack[LoginRequest]) -> UserSession:
        raise NotImplementedError
```

Зарегистрируйте bounded flow отдельно:

```python
flow = protection_flow(
    LOGIN_PROTECTION,
    acquire=AsyncProtectionApi.acquire,
    solve=True,
    verify=AsyncProtectionApi.verify,
)

config = ClientConfig(
    protections=(flow,),
    protection_solvers=SolverBindings(
        bind_solver(LOGIN_PROTECTION, CaptchaSolver()),
    ),
)
```

Порядок выполнения фиксирован: `acquire → solve → verify → projection → private writers → login`.
Для CSRF используйте только
`acquire`. Для CAPTCHA без server-side verification пропустите `verify`. Один result может
заполнить несколько `FromProtection` fields, включая поля вложенных target-моделей.

Если flow, solver или source field отсутствует, вызов завершается до acquire, middleware и сети.
Solver можно заменить fake-реализацией в тесте без изменения операции.

## Conditional и domain protection

Challenge, который появляется только в конкретном ответе, остаётся response case. Автоматический
solve/replay подключается как scoped client policy. Cloudflare и другие внешние WAF также
принадлежат client policy, а не decorator операции.
