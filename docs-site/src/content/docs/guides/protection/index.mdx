Protection разделяет обязательный flow операции, proactive before-call policy и conditional
response challenge. Выбирайте ровно тот lifecycle, который соответствует протоколу сервера.

```bash
uv add eazy-sdk-presets
```

## Установите first-party preset

Передайте solver factory и установите returned preset одним immutable выражением. Preset сам
маршрутизирует policy в `before_call_policies` или `challenge_policies` и добавляет solver binding.

```python target
guard = cloudflare.challenge_pages(
    scope=host("api.example.test"),
    solver=CloudflareSolver(),
)

config = ClientConfig(
    network_identity=identity,
).with_protection(guard)
```

Не передавайте solver, если framework связывает solvers через SDK-level DI. В этом случае bundle
сохраняет unbound requirement, а missing binding обнаруживается до providers и transport I/O.

## Mandatory CAPTCHA перед login

Public request содержит только данные caller. Managed поля находятся в private wire-модели и
заполняются одним protection result атомарно.

```python target
flow = protection_flow(
    LOGIN_PROTECTION,
    acquire=AsyncProtectionApi.acquire,
    solve=True,
    verify=AsyncProtectionApi.verify,
)

config = ClientConfig(
    operation_protections=(flow,),
    operation_protection_solvers=SolverBindings(
        bind_solver(LOGIN_PROTECTION, CaptchaSolver()),
    ),
)
```

Порядок фиксирован: `acquire → solve → verify → projection → private writers → request`.

## Advanced: custom compound challenge

Этот пример описывает KAD-подобный challenge, который возвращает две private cookies. Они
отсутствуют в сигнатуре operation и не хранятся в auth registry.

```python target
from dataclasses import dataclass

from eazy_sdk import ClientConfig
from eazy_sdk.protection import (
    ChallengeSolverBindings,
    ResponseSignal,
    SolverRequirement,
    bind_challenge_solver,
    challenge_policy,
    network_identity,
    private_bindings,
    private_cookie,
    rejected_before_origin,
    until_rejected,
)

@dataclass(frozen=True)
class KadChallenge:
    revision: str

@dataclass(frozen=True)
class KadClearance:
    pr_fp: str
    wasm: str

KAD_WASM_SOLVER = SolverRequirement[KadChallenge, KadClearance]("kad.wasm")

KAD_WASM_POLICY = challenge_policy(
    identity="kad.wasm",
    revision=1,
    scope=host("kad.arbitr.ru"),
    signal=KAD_CHALLENGE,
    solver=KAD_WASM_SOLVER,
    apply=private_bindings(
        private_cookie("pr_fp", field="pr_fp"),
        private_cookie("wasm", field="wasm"),
    ),
    persistence=until_rejected(scope=network_identity()),
    replay=rejected_before_origin(max_replays=1),
    challenge_identity=lambda challenge: challenge.revision,
)

config = ClientConfig(
    challenge_policies=(KAD_WASM_POLICY,),
    challenge_solvers=ChallengeSolverBindings(
        bind_challenge_solver(KAD_WASM_SOLVER, KadSolver()),
    ),
)
```

Low-level lifecycle collections и `ChallengeSolverBindings` нужны авторам frameworks и custom
policies. Для first-party presets используйте `with_protection()`.

Compiler проверяет conflicts с caller inputs, auth, dependency, signature и другими private
writers. Runtime сначала выбирает и валидирует весь batch, затем применяет один patch. При
повторном challenge старая revision инвалидируется; совместимые concurrent calls разделяют один
solve по полному state key.

## Network identity и capabilities

Network-scoped policies требуют `NetworkIdentity` или `NetworkIdentityProvider`. Runtime разрешает
identity отдельно для каждой attempt и использует одно значение для cache/single-flight key,
`SolveContext`, solution validation и handler-owned connection profile. Rotating handler и config
должны ссылаться на один provider instance; конфликт двух источников отклоняется до I/O.

Solver явно объявляет `ProtectionCapabilities`: buffered response, cookie jar, JavaScript, browser
и sticky network identity. Missing capability вызывает `ProtectionCapabilityMismatch` до solve и
emit. Clearance solution может объявить `expected_identity`; mismatch вызывает
`ProtectionIdentityMismatch` до publication. Ошибки и `repr` не содержат proxy credentials,
cookies или identity values.

Shared state использует single-flight по полному key. Lock удаляется после последнего holder или
waiter, включая exception и cancellation; cached state живёт независимо от lock object.
