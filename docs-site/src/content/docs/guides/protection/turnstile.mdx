Widget и preclearance принадлежат разным lifecycle. Installable presets сами выбирают правильные
collections; caller устанавливает оба через один immutable merge.

```python target
widget = cloudflare.turnstile_widget(
    scope=operation("login"),
    solver=TurnstileTokenSolver(),
    apply=form_field("cf-turnstile-response"),
)

preclearance = cloudflare.turnstile_preclearance(
    scope=host("api.example.test"),
    site_key="public-site-key",
    page_url="https://api.example.test/login",
    solver=TurnstileClearanceSolver(),
)

config = ClientConfig(
    network_identity=identity,
).with_protection(widget, preclearance)
```

Widget решается только после matched response и использует replay safety. Preclearance решается до
origin request, переиспользуется до expiry и привязан к network identity. Оба solver-а явно
объявляют `ProtectionCapabilities`; clearance solver возвращает
`expected_identity=context.network_identity`.
