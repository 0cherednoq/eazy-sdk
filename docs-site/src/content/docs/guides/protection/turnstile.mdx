Widget and preclearance guards use different lifecycle stages. Install both descriptors through one
immutable config merge:

```python target
widget = cloudflare.turnstile_widget(
    scope=operation("login"),
    solver=TurnstileTokenSolver(),
    apply=form_field("cf-turnstile-response"),
)

preclearance = cloudflare.turnstile_preclearance(
    scope=host("api.example.test"),
    site_key="public-site-key",
    page_url="https://api.example.test/login",
    solver=TurnstileClearanceSolver(),
)

config = ClientConfig().with_protection(widget, preclearance)
```

The widget solver runs only after a matching response and uses the configured replay proof.
Preclearance runs before the origin request and can be reused until expiry within the current
handler session.

Both solvers implement only their typed challenge-to-solution contract. The runtime does not ask
whether they use JavaScript, a browser, WASM, or an external service. If preclearance and HTTP must
share a network path, build both from the same fixed session or lease. Rotate transport by creating
a new client.
