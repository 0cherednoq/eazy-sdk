Тип результата операции — это и есть успешный случай. `HttpOperation[User]` означает «`200`,
JSON, модель `User`»; ничего дополнительно объявлять не нужно.

```python
from dataclasses import dataclass

from eazy_sdk import Http, HttpOperation, Path, SyncApi, op

@dataclass(frozen=True, slots=True, kw_only=True)
class GetUser(HttpOperation[User]):
    __http__ = Http.get("/users/{user_id}")

    user_id: Path[int]

class UsersApi(SyncApi):
    get_user = op(GetUser)

users = UsersApi(client)
user = users.get_user(user_id=42)
envelope = users.get_user.with_response(user_id=42)

assert envelope.value == User(id=42, name="Ada")
print(envelope.status_code)
print(envelope.headers.get("x-request-id"))
print(envelope.response.raw_response)
```

Request: `GET /users/42`. Response: status `200`, header `Content-Type: application/json`, JSON
`{"id":42,"name":"Ada"}`. Обычный вызов возвращает `User`; `.with_response(...)` выполняет ту же
операцию и добавляет HTTP metadata, не меняя parser или response case.

Модель создаётся через настроенный `ModelAdapterRegistry`: dataclass, Pydantic v2, msgspec и
зарегистрированные custom adapters. Примеры — в {doc}`руководстве по сериализации моделей
</api-reference/models-codecs>`.

## Семья выводится из модели

Какой экстрактор читает ответ, решает модель, а не декларация: модель, поля которой несут
CSS/XPath-селекторы, читается документным бэкендом, любая другая — как JSON.

```python
@dataclass(frozen=True, slots=True)
class CatalogPage:
    title: Annotated[str, CSS("h1::text")]

@dataclass(frozen=True, slots=True, kw_only=True)
class GetCatalogue(HttpOperation[CatalogPage]):   # Html, потому что есть селекторы
    __http__ = Http.get("/catalogue/page-{page}.html")

    page: Path[int]
```

`str` означает текстовый ответ, `bytes` — бинарный, `None` — пустое тело. `Json(...)`, `Html(...)`,
`Text()`, `Bytes()`, `Empty()` пишут явно, когда нужно задать медиа-тип, статус или условие.

## Несколько успешных случаев

`success=` нужен там, где успешных ответов больше одного или у ответа особый статус:

```python
@dataclass(frozen=True, slots=True, kw_only=True)
class CreateOrder(HttpOperation[Order]):
    __http__ = Http.post(
        "/orders",
        success={201: Order, 202: Accepted},
    )

    item: JsonField[str]
```

Значение по ключу — модель, представление или их список: один статус может документировать
несколько форм, а различает их `when=`. Его принимает любое представление: `Json`, `Html`,
`Extracted`, `Parsed`, `Text`, `Bytes` и `Empty`.

Если два случая подошли к одному ответу, выигрывает более конкретный. Порядок сравнения такой:

1. случай, заявивший критерий, важнее случая без критерия;
2. точный статус важнее диапазона `"4xx"`, диапазон важнее `DEFAULT`;
3. явная медиа важнее `*/*`, а `*/*` важнее её отсутствия;
4. объявление операции важнее объявления её сервиса, а сервиса — важнее клиента.

Критерий стоит первым, потому что это более узкое утверждение. «`200`, и тело выглядит как
страница защиты» говорит больше, чем «`200`». Благодаря этому сервис, объявивший свои страницы
защиты один раз на диапазоне статусов, не проигрывает каждой операции, объявившей обычный успех
на точном статусе. Операция, которая действительно владеет статусом вопреки условному случаю,
заявляет собственный `when=`.

Настоящая ничья — два одинаково конкретных случая — остаётся `AmbiguousResponseError`: её
разрешает автор, а не библиотека.

## Конверт сервиса

Многие API кладут полезную нагрузку внутрь конверта. Указатель на неё объявляется один раз на
сервисе — как JSON-указатель RFC 6901:

```python
class ShopApi(SyncApi):
    unwrap = "/data"

    get_order = op(GetOrder)
    get_catalogue = op(GetCatalogue)
```

Ответ `{"data": {"id": "o-1", "total": 500}, "meta": {...}}` разбирается в `Order`, и ни одна
операция про конверт не знает. Указатель применяется только к случаям, построенным из «голой»
модели: явный `Json(Order)` остаётся тем, что написано. Если пути в документе нет — это
`MalformedResponseError`, а не «поле пропало».

Сервис, объявивший `protocol` (конверт протокола, см. {doc}`протоколы </guides/protocols>`),
`unwrap` объявлять не может: конверт уже выбирает полезную нагрузку.

## Конверт с бизнес-статусом

`unwrap` подходит конверту, который только оборачивает. Но многие сервисы сообщают неуспех внутри
конверта, оставляя статус `200`:

```json
{"Success": false, "Result": null, "Message": "Дело не найдено"}
```

Такой конверт читается не указателем, а правилом на самой модели. Модель объявляет атрибут
`__envelope__`: `succeeds` отвечает, успешен ли конверт, `payload` говорит, где внутри лежит
полезная нагрузка.

```python
from dataclasses import dataclass

from eazy_sdk import Http, HttpOperation, SyncApi, op
from eazy_sdk.response import ApiError, Envelope, Json

@dataclass(frozen=True)
class CaseFile:
    number: str

@dataclass(frozen=True)
class CaseEnvelope:
    Result: CaseFile | None
    Success: bool
    Message: str | None = None

    __envelope__ = Envelope(succeeds=lambda r: r.Success, payload=lambda r: r.Result)

class CaseNotFound(ApiError[CaseEnvelope]):
    pass

@dataclass(frozen=True, slots=True, kw_only=True)
class GetCase(HttpOperation[CaseFile]):
    __http__ = Http.get(
        "/cases",
        success={200: Json(CaseEnvelope)},
        errors={200: (Json(CaseEnvelope), CaseNotFound)},
    )

class CasesApi(SyncApi):
    get_case = op(GetCase)
```

Один предикат объявляет обе половины: успешный случай совпадает, когда `succeeds` отвечает «да»,
случай ошибки — когда «нет». Ответ с `"Success": false` поднимает `CaseNotFound` — обычный
`ApiError`, который участвует в `errors=`, попадает в `ErrorSummary` и проходит через слои retry
и защиты. Проверка `if not response.success: raise` в коде вызывающего больше не нужна.

`payload` применяется только к успешному случаю, поэтому результат операции — `CaseFile`, а поля
`Success` и `Message` не видны вызывающему коду. Случай ошибки сохраняет весь конверт: `Message`
живёт именно там, и `CaseNotFound.error.Message` его отдаёт.

Объявление — атрибут класса, а не метод, поэтому работает на всех четырёх библиотеках моделей.
Для `TypedDict` меняется только способ доступа, потому что значение там действительно словарь:

```python
__envelope__ = Envelope(succeeds=lambda r: r["Success"], payload=lambda r: r["Result"])
```

Правило хранит обычные вызываемые объекты, поэтому сложное условие пишется обычной функцией с
аннотацией, а не языком выражений:

```python
def _succeeds(envelope: CaseEnvelope) -> bool:
    return envelope.Success and envelope.Result is not None
```

Один и тот же объект `Envelope(...)` присваивается многим моделям, либо объявляется один раз в
базовом классе и наследуется: чтение идёт обычным поиском атрибута.

Если модель менять нельзя — например, она сгенерирована — то же решение принимает `accept=` на
кейсе: `Json(ThirdParty, accept=lambda r: r.status == "ok")`. Он отвечает на другой вопрос,
«подходит ли этот кейс», поэтому читается как написан и на успехе, и на ошибке, и переопределяет
правило модели.

## Одно объявление на много операций

Успешные случаи задают тип результата, поэтому от сервиса они не наследуются. Повтор убирается не
вторым механизмом наследования, а обычной функцией: `Json(...)` — значение, и его собирает
фабрика.

```python
def wrapped[T](model: type[T]) -> Json[T]:
    return Json(model, unwrap="/data")

@dataclass(frozen=True, slots=True, kw_only=True)
class GetOrder(HttpOperation[Order]):
    __http__ = Http.get("/orders/{order_id}", success=wrapped(Order))

    order_id: Path[str]
```

Так же устроены и штатные хелперы: `rpc_result(Model)` из {doc}`протоколов </guides/protocols>` —
это ровно `Success(200, Json(Model, extractor=RESULT_EXTRACTOR))`, собранный функцией. Отдельного
«декодера по умолчанию» на роутере нет намеренно: он делал бы форму ответа невидимой в месте, где
объявлен возвращаемый тип.
