## Контракт

```python
from dataclasses import dataclass

from pydantic import BaseModel

from eazy_sdk import Http, HttpOperation, JsonField, op
from eazy_sdk.response import ApiError

class LoginProblem(BaseModel):
    code: str
    message: str

class InvalidPasswordError(ApiError[LoginProblem]):
    pass

class UserNotFoundError(ApiError[LoginProblem]):
    pass

@dataclass(frozen=True, slots=True, kw_only=True)
class Login(HttpOperation[UserSession]):
    __http__ = Http.post(
        "/auth/login",
        errors={401: InvalidPasswordError, 404: UserNotFoundError},
    )

    username: JsonField[str]
    password: JsonField[str]
```

Модель ошибки объявлена один раз — в `ApiError[LoginProblem]`, — поэтому в `errors=` достаточно
самого класса исключения. Ключ — статус (`404`), диапазон (`"5xx"`) или `DEFAULT` — последний
только в `fallback=`, потому что «на всё остальное» это не такой же случай, как `404`.

Если исключение приложения не должно наследовать библиотечный класс, объявите пару
«модель, фабрика»:

```python
class Refused(Exception):
    def __init__(self, problem: LoginProblem, context: object) -> None:
        self.problem = problem
        super().__init__(problem.message)

__http__ = Http.post("/auth/login", errors={403: (LoginProblem, Refused)})
```

## Обработка

```python
try:
    session = await sdk.auth.login(username="ada@example.test", password="wrong")
except InvalidPasswordError as exc:
    print(exc.error.message)
except UserNotFoundError as exc:
    print(exc.error.message)
```

`ApiError` хранит typed payload в `.error` и response context в `.context`. Не используйте status
code branching после обычного вызова: documented error case уже выбрал точный exception type.

Свойство `.summary` доступно всегда и возвращает `ErrorSummary` — operation_id, статус, media
type, номер попытки, метод и редактированный target. Именно она переживает `pickle`: в очередь
задач или в отчёт об ошибке уезжает сводка, а не тело ответа с его заголовками.

## Ошибки, общие для сервиса и хоста

Ошибки — единственная часть контракта ответа, которая складывается: сервис объявляет `errors`, и
они добавляются к объявленным операцией. При совпадении статуса выигрывает случай, объявленный
ближе к операции.

```python
class ShopApi(SyncApi):
    errors = ({429: RateLimited},)

    login = op(Login)
```

Клиент может объявить то же самое по адресу — для ошибок, которыми хост отвечает независимо от
того, какой SDK с ним говорит:

```python
config = ClientConfig(errors={"api.shop.example": {503: AccessBlocked}})
```

Это самый внешний слой: операция важнее сервиса, сервис важнее клиента.

Ответ с неизвестным status/media type даёт `UnexpectedResponseError`; если тело пришло документной
медиа, а все кандидаты — структурные модели, сообщение это называет. Валидный case с malformed
payload даёт `MalformedResponseError`. Эти ошибки означают нарушение контракта upstream и не
смешиваются с ожидаемыми `401`/`404`.
