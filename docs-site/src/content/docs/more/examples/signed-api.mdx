Eazy SDK сериализует JSON до подписи. Signer и HTTP adapter получают одни и те же bytes, поэтому
HTTPX или Requests не пересобирают body после вычисления HMAC.

## Обмен по сети

:class-container: http-exchange

::::{grid-item}
:class: http-panel http-panel--request

**→ Request** · ``POST /v1/payments``

```json
{
  "method": "POST",
  "url": "/v1/payments",
  "headers": {
    "Content-Type": "application/json",
    "X-Signature": "06f06f38d18688c89e0e40b1f934d92bc4c51e3ecf74b1012a8332d64227a1aa"
  },
  "body": {"amount": "49.90", "currency": "EUR"}
}
```

## Структура примера

```text
payments/
├── models.py      # CreatePaymentInput и Payment
├── signing.py     # SigningKeyRequirement и HMAC rule
├── api.py         # Декорированный POST /v1/payments
└── main.py        # key provider и вызов клиента
```

Signature base для примера:

```text
POST
/v1/payments
0e51c73f01851ebc29c3a3fc6b220768f6b34123a6285ece2a5f6c897f924f13
```

Последняя строка является SHA-256 от bytes
`{"amount":"49.90","currency":"EUR"}`. Полный код правила подписи, API-метода и key provider
находится в {doc}`руководстве по подписи запросов </signing>`.

При retry, redirect или auth refresh Eazy SDK заново готовит request и считает новую подпись.
Timestamp и nonce должны появиться до signing через auth, dependency или attempt contribution.
