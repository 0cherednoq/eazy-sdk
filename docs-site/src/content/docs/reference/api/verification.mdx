## Модели

```python
VerificationChallenge(id=..., kind=..., target=..., meta=...)
VerificationAccepted(next_verification=..., session=..., meta=...)
```

## Методы

```python
result = await flow.verify(pending, proof)
result = await flow.resume(identifier)
pending = await flow.resend(pending)
```

`verify(...)` возвращает завершённую регистрацию или следующий challenge.

`VerificationChallenge` содержит стабильные `id` и `kind`, optional `target` и `meta`.
`VerificationAccepted` может вернуть следующую verification, session или metadata успешного
шага.

`flow.resume(identifier)` загружает pending registration после перезапуска. `flow.resend(pending)`
заменяет challenge с сохранением chain. `flow.verify(pending, proof)` проверяет, что challenge
принадлежит текущей revision, поэтому устаревший proof не может завершить более новый flow.

Provider из `verification={kind: provider}` может получить proof автоматически. Если provider не
зарегистрирован, caller передаёт proof явно.
