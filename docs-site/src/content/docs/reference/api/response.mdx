## Одна успешная case

Тип результата операции и есть успешный случай:

```python
from dataclasses import dataclass

from pydantic import BaseModel

from eazy_sdk import AsyncApi, Http, HttpOperation, Path, op

class User(BaseModel):
    id: int

@dataclass(frozen=True, slots=True, kw_only=True)
class GetUser(HttpOperation[User]):
    __http__ = Http.get("/users/{user_id}")

    user_id: Path[int]

class UsersApi(AsyncApi):
    get_user = op(GetUser)
```

Семья читается из модели: модель с CSS/XPath-селекторами означает документ, любая другая модель
означает JSON, `str` означает текст, `bytes` означает байты, а `None` означает пустое тело. Явные
`Json(status=201)`, `Html(...)`, `Text()`
нужны, когда важны статус, медиа-тип или условие `when=`/`accept=`.

## Несколько случаев

`success=`, `errors=` и `fallback=` принимают мэппинг селектора на случай:

```python
__http__ = Http.get(
    "/users/{user_id}",
    success={200: User, 202: PendingUser},
    errors={404: UserNotFound, "5xx": ServiceUnavailable},
    fallback=Problem,
)
```

Ключом служит статус, диапазон (`"4xx"`, `"5xx"`) или `DEFAULT`; `DEFAULT` допустим только в `fallback=`.
Значение может быть моделью, представлением, классом `ApiError[Model]`, парой `(Model, factory)` или их списком.
Эквивалентная запись через `Responses(success=(Success(...),), errors=(Error(...),))` остаётся
доступной: это то же значение, собранное вручную.

| Representation | Результат |
|---|---|
| `Json(Model, media_type=...)` | dataclass, Pydantic, msgspec или custom model adapter |
| `Html(Model, media_type=...)` | CSS/XPath extraction с последующим model adapter |
| `Extracted(Model, using=...)` | Custom primitive extractor с последующим model adapter |
| `Parsed(Model, using=...)` | Custom response parser |
| `Text(media_type=...)` | `str` |
| `Bytes(media_type=...)` | `bytes` |
| `Empty(media_type=...)` | `None`, только для пустого body |

Status selector может быть `int`, `StatusRange(start, end)` или `DEFAULT`.

## Typed callable parser

Для одного custom model используйте фабрику, связывающую callback с типом заранее:

```python
from eazy_sdk.ext import Malformed, NoMatch, ParseAttempt, ParsedValue
from eazy_sdk.response import ResponseContext, callable_parser

def parse_challenge(
    context: ResponseContext[object],
) -> ParseAttempt[Challenge]:
    if context.response.status_code != 403:
        return NoMatch()
    return ParsedValue(Challenge(context.text.value or ""))

CHALLENGE_PARSER = callable_parser(Challenge, parse_challenge)
```

Runtime не передаёт callback-у `type[object]`. Несовместимый return type отклоняют mypy и
Pyright. Для multi-model parser реализуйте advanced `ResponseParser` SPI. Старого
`CallableParser` и compatibility alias нет.

## Результаты и ошибки

Обычный вызов даёт значение success case. `method.with_response(...)` возвращает
`ResponseEnvelope`: `value`, `status_code`, `headers` и normalized raw `response`.

В `ApiError[T]` доступны typed `.error` и безопасный `.context`. Свойство `.summary` всегда доступно
и даёт `ErrorSummary` с operation_id, статусом, media type, номером попытки, методом и
редактированным target. Именно она переживает `pickle`: сериализованное исключение не несёт ни
тела ответа, ни его заголовков, а восстановленный `.context` содержит `ErrorSummary`.

Ошибки классификации разделены:

- `UnexpectedResponseError`: подходящей case нет; если ответ пришёл документной медиа, а все
  кандидаты структурные, сообщение это называет;
- `MalformedResponseError`: body не разобран выбранным parser/extractor;
- `AmbiguousResponseError`: совпало больше одной одинаково специфичной case. При сравнении наличие
  заявленного критерия важнее его отсутствия, точный статус важнее диапазона, а диапазон важнее
  `DEFAULT`. Явная медиа важнее wildcard и отсутствия медиа; кейс операции важнее кейса сервиса,
  а кейс сервиса важнее кейса клиента. Критерием служит `when=`, `accept=` или тег, который
  объявила модель.

Parsing session создаётся один раз на response attempt, поэтому custom parser или extractor может
кэшировать decoded document по identity.
