## Одна успешная case

В hand-written SDK стандартный ответ объявляется рядом с operation:

```python
from typing import Annotated

from pydantic import BaseModel
from eazy_sdk import AsyncApi, api
from eazy_sdk.request import Path
from eazy_sdk.response import Json

class User(BaseModel):
    id: int

class UsersApi(AsyncApi):
    @api.get("/users/{user_id}", response=Json(status=200))
    async def get_user(self, *, user_id: Annotated[int, Path()]) -> User:
        raise NotImplementedError
```

`Json()` получает `User` из return-аннотации. Status по умолчанию равен `200`; `when=` задаёт
дополнительное условие case. То же правило поддерживает `Html()`.

## Полный `Responses`

Используйте advanced contract, когда успехов несколько или нужна сложная arbitration:

```python
RESPONSES = Responses(
    success=(
        Success(200, Json(User)),
        Success(202, Json(PendingUser)),
    ),
    errors=(Error(404, Json(Problem), exception=UserNotFound),),
    fallback=Error(DEFAULT, Text()),
)
```

| Representation | Результат |
|---|---|
| `Json(Model, media_type=...)` | dataclass, Pydantic, msgspec или custom model adapter |
| `Html(Model, media_type=...)` | CSS/XPath extraction → model adapter |
| `Extracted(Model, using=...)` | Custom primitive extractor → model adapter |
| `Parsed(Model, using=...)` | Custom response parser |
| `Text(media_type=...)` | `str` |
| `Bytes(media_type=...)` | `bytes` |
| `Empty(media_type=...)` | `None`, только для пустого body |

Status selector может быть `int`, `StatusRange(start, end)` или `DEFAULT`.

## Typed callable parser

Для одного custom model используйте фабрику, связывающую callback с типом заранее:

```python
from eazy_sdk.ext import Malformed, NoMatch, ParseAttempt, ParsedValue
from eazy_sdk.response import ResponseContext, callable_parser

def parse_challenge(
    context: ResponseContext[object],
) -> ParseAttempt[Challenge]:
    if context.response.status_code != 403:
        return NoMatch()
    return ParsedValue(Challenge(context.text.value or ""))

CHALLENGE_PARSER = callable_parser(Challenge, parse_challenge)
```

Runtime не передаёт callback-у `type[object]`. Несовместимый return type отклоняют mypy и
Pyright. Для multi-model parser реализуйте advanced `ResponseParser` SPI. Старого
`CallableParser` и compatibility alias нет.

## Результаты и ошибки

Обычный вызов возвращает значение success case. `method.with_response(...)` возвращает
`ResponseEnvelope`: `value`, `status_code`, `headers` и normalized raw `response`.

`ApiError[T]` содержит typed `.error` и безопасный `.context`. Свойство `.summary` доступно
всегда и возвращает `ErrorSummary` — operation_id, статус, media type, номер попытки, метод и
редактированный target. Именно она переживает `pickle`: сериализованное исключение не несёт ни
тела ответа, ни его заголовков, а восстановленный `.context` — это `ErrorSummary`.

Ошибки классификации разделены:

- `UnexpectedResponseError` — подходящей case нет; если ответ пришёл документной медиа, а все
  кандидаты структурные, сообщение это называет;
- `MalformedResponseError` — body не разобран выбранным parser/extractor;
- `AmbiguousResponseError` — совпало больше одной одинаково специфичной case. Специфичность
  считается так: точный статус > диапазон > `DEFAULT`, явная медиа > wildcard > её отсутствие,
  `when=` > его отсутствие, кейс операции > кейс сервиса > кейс клиента.

Parsing session создаётся один раз на response attempt, поэтому custom parser или extractor может
кэшировать decoded document по identity.
