`Client` принимает Zapros `BaseHandler`, а `AsyncClient` — `AsyncBaseHandler`. Handler является
единственной transport extension boundary.

```python
from zapros import AsyncStdNetworkHandler

from eazy_sdk import AsyncClient, ClientConfig

client = AsyncClient(
    base_url="https://api.example",
    handler=AsyncStdNetworkHandler(),
    config=ClientConfig(timeout=5.0),
)
```

По умолчанию client владеет handler. Передайте `owns_handler=False`, если lifecycle handler
остаётся у caller. Sync client отклоняет async handler и наоборот.

`CallOptions` управляет timeout, retry/redirect budgets и replay одного вызова. Auth,
middleware, retry, redirect, rate limit и protection остаются в общем executor; каждый attempt
создаёт новый Zapros `Request`.

## Root SDK convenience

`SyncApi`, `AsyncApi` и `api_group()` создают typed root без forwarding wrappers:

```python
from eazy_sdk import AsyncApi, api_group

class StoreSdk(AsyncApi):
    users = api_group(UsersApi)
    orders = api_group(OrdersApi)

async with StoreSdk.from_handler(
    handler=handler,
    base_url="https://api.example",
) as sdk:
    user = await sdk.users.get_user(user_id=42)
```

Группы создаются лениво и используют тот же client. Ownership задаётся явно:

| Конструктор | Кто закрывает ресурсы |
|---|---|
| `from_handler(..., owns_handler=True)` | root → новый client → handler |
| `from_handler(..., owns_handler=False)` | root закрывает client, caller сохраняет handler |
| `from_client(client)` | caller сохраняет client |
| `from_client(client, owns_client=True)` | root закрывает client |

`from_handler()` регистрирует scoped SDK factory через существующий `bind_sdk()` lifecycle.
Scoped auth facades никогда не владеют parent resources.

Root и API groups не сериализуют пользовательские вызовы: независимые calls можно выполнять
конкурентно в пределах concurrency-контракта выбранного handler. Встроенные auth/protection caches
сами обеспечивают заявленный single-flight. Не запускайте новые calls одновременно с
`close()`/`aclose()`; закрытие выполняется после завершения использующих root задач.

## Синхронный клиент и event loop

`Client` не вызывает `asyncio.run()` на каждый запрос: у каждого потока есть свой переиспользуемый
`asyncio.Runner`, который создаётся лениво и закрывается в `close()`. После каждого вызова текущий
loop потока сбрасывается, как это делает `asyncio.run()`. Вызов `Client` из потока, в котором уже
работает event loop (Jupyter, обработчик `asyncio`-сервера), поднимает `EventLoopConflictError`:
используйте там `AsyncClient`. Несколько потоков могут делить один `Client`; single-flight
protection-локи не привязаны к loop.

## Client configuration

`ClientConfig` включает dependencies, auth, middleware, `retry=`, rate limiter, signing key provider,
crypto и одну группу `protection=` (`ProtectionBundle`). First-party preset, `Guard` или custom `challenge_guard()`
устанавливайте через `ClientConfig(guards=[...])` либо эквивалентный immutable
`config.with_protection(guard)`; `client.invalidate_protection(*guards_or_names)` сбрасывает
закэшированные решения без доступа к runtime. `ProtectionBundle` объединяет
`operation_protections`, `before_call_policies`, `challenge_policies` и `solver_bindings`;
`config.bundle` возвращает установленную (или пустую) группу.

Managed protection state принадлежит одному client/handler session и очищается при закрытии
client. Proxy, User-Agent и impersonation задаются при construction handler-а: фабрики
`Client.httpx(proxy=...)`, `Client.requests(proxy=...)`, `Client.curl_cffi(proxy=..., impersonate=...)`
и их async-варианты настраивают создаваемую сессию и объявляют результат в
`HandlerProfile.proxy`/`HandlerProfile.impersonation` (для чужой сессии `proxy=` — только
декларация того, что она уже использует). Именно объявленный proxy входит в transport identity
managed clearance. Для rotation создайте новый handler и client; per-attempt transport identity
provider отсутствует.

## Ad-hoc HTTP

```python
response = await client.request(
    "PATCH",
    "/experimental",
    params={"dry_run": "true"},
    json={"enabled": True},
    options=CallOptions(timeout=3.0),
)
```

`delete`, `get`, `head`, `options`, `patch`, `post`, `put` и `trace` возвращают
`NormalizedResponse` и делегируют тому же `request(...)`. Повторяющиеся query names запрещены;
collection требует явного scalar codec.

## Stability и extension boundaries

| Поверхность | Статус | Правило расширения |
|---|---|---|
| `SyncApi`, `AsyncApi`, `api_group`, `Client`, `AsyncClient` | Public | Используйте напрямую; ownership всегда задаётся конструктором |
| `api.*`, request markers, `Responses`, `ResponseParser` | Public authoring/SPI | Реализуйте документированные protocol-ы, не наследуйтесь от internal compiler types |
| Zapros `BaseHandler` / `AsyncBaseHandler` | Transport SPI | Единственная граница собственной сетевой интеграции |
| `eazy_sdk.testing` | Public test support | Наблюдает фактический Zapros request, не заменяет preparation |
| `eazy_sdk.ext` | Alpha implementation SPI | Используйте только имена из `__all__`; полный контракт и removed internals перечислены в {doc}`Extension SPI </api-reference/extensions>` |
| `eazy_sdk.compile.*`, executor stages и compiled records | Private | Не импортируйте и не сохраняйте их между версиями |
