## HMAC

```python
hmac_sha256(*, key, base, output)
```

## Данные подписи

```python
join(*parts, separator=b"", prefix=b"", suffix=b"")
method()
path()
target()
query(...)
body_digest(...)
canonical_json(...)
```

## Результат

```python
header_output(name, encoding="hex")
query_output(name, encoding="hex")
cookie_output(name, encoding="hex")
body_output(name, encoding="hex")
```

Ключ задаётся через `SigningKeyRequirement(name)`.

`join(...)` объединяет компоненты с явным separator. Доступные projections включают `header(...)`,
`query(...)`, `canonical_json(...)`, `wire_body()` и `previous_signature(...)`.

Output может записать подпись в header, query, cookie или body. `encoding` принимает `hex`,
`base64` или `raw`; `position` фиксирует место для exact wire API.

Подпись объявляется **по месту объявления**: параметром `signing=` операции или атрибутом
`signing` роутера/миксина сервиса, наследуемым по MRO. Адресных (host/path) правил подписи нет:
глядя на операцию, всегда видно, подписана она или нет, а опечатка в правиле не может оставить
запрос молча неподписанным. Роутер может объявить `signed = True` — тогда операция без подписи
отвергается при компиляции.

База подписи считается от тех же байтов, которые уйдут, — в том числе когда тело зашифровано
целиком, — и кодируется той же `JsonPolicy`, что и тело
(см. {doc}`Представление запроса </guides/requests/representation>`).

`Identity.key_provider` является callable
`(SigningKeyRequirement) -> SigningKey`. Secrets отсутствуют в arguments операции и redacted в
`repr`.
