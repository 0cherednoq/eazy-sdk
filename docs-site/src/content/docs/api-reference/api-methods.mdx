Операция — это класс: его поля описывают запрос, `__http__` — метод, путь и всё остальное, что
операция объявляет. Роутер (`SyncApi` или `AsyncApi`) публикует операцию через `op(...)`, и
публичной сигнатурой SDK становится конструктор класса.

## Операция как класс

```python
from dataclasses import dataclass

from pydantic import BaseModel

from eazy_sdk import UNSET, AsyncApi, Http, HttpOperation, Omittable, Path, Query, op

class User(BaseModel):
    id: int

@dataclass(frozen=True, slots=True, kw_only=True)
class GetUser(HttpOperation[User]):
    __http__ = Http.get("/users/{user_id}")

    user_id: Path[int]
    include: Query[Omittable[str]] = UNSET
    page: Query[int] = 1

class UsersApi(AsyncApi):
    get_user = op(GetUser)
```

`HttpOperation[User]` называет тип результата. Класс может быть dataclass, Pydantic-моделью или
msgspec-структурой; требование одно — он frozen, потому что запрос является значением. Значения по
умолчанию — обычные Python defaults, включая `default_factory`; поле, которое иногда не нужно
отправлять вовсе, объявляется `Omittable[T] = UNSET`.

HTTP-параметры всегда keyword-only: конструктор объявляется `kw_only=True`.

## Декоратор как короткая форма

`@api.get(...)` синтезирует ровно такой же frozen-класс — он доступен как
`UsersApi.get_user.Operation`. Отличия двух форм и когда какая уместна — на странице
{doc}`Объявление операции </guides/requests/declarative>`.

## Ответ операции

Тип результата и есть успешный случай; `success=` нужен, только когда случаев несколько или у
ответа особый статус. Ошибки объявляются мэппингом:

```python
from dataclasses import dataclass

from pydantic import BaseModel

from eazy_sdk import AsyncApi, Http, HttpOperation, Path, op
from eazy_sdk.response import ApiError

class NotFound(BaseModel):
    detail: str

class UserNotFound(ApiError[NotFound]):
    pass

@dataclass(frozen=True, slots=True, kw_only=True)
class GetUser(HttpOperation[User]):
    __http__ = Http.get("/users/{user_id}", errors={404: UserNotFound})

    user_id: Path[int]

class UsersApi(AsyncApi):
    errors = ({429: RateLimited},)

    get_user = op(GetUser)
```

Ошибки операции складываются с `errors` роутера; `inherit_errors=False` отключает наследование.
При совпадении статуса выигрывает случай, объявленный ближе к операции. Подробности — в
{doc}`Ошибки API </guides/responses/errors>`.

## Namespace `api` и `Http`

Одни и те же глаголы в двух формах:

- `Http.get`, `Http.post`, `Http.put`, `Http.patch`, `Http.delete`, `Http.head`, `Http.options`,
  `Http.trace` — для класса;
- `api.get`, `api.post`, ... — для декоратора.

Для другого валидного HTTP token есть общий вход: `Http.request("PROPFIND", "/resources")` и
`api.request("PROPFIND", "/resources")`. Невалидный token отклоняется при создании спецификации.

## Параметры `Http.*` и `api.*`

| Параметр | Назначение | Default |
|---|---|---|
| `path` | URL path с `{placeholder}` | обязательный |
| `success` | Успешные случаи, когда их больше одного | тип результата |
| `errors` | Typed error cases: `{404: NotFound}` | `{}` |
| `fallback` | Случай «на всё остальное» | — |
| `inherit_errors` | Добавить `errors` роутера | `True` |
| `operation_id` | Стабильная identity операции | имя класса или метода |
| `security` | Auth scheme или policy | inherited |
| `requires`, `inject` | Managed request dependencies | `()` |
| `signing` | Request signatures | inherited |
| `crypto` | Payload crypto | inherited |
| `protections` | Mandatory protection requirements | `()` |
| `wire` | `Wire` — представление запроса на проводе | inherited |
| `projection` | `BodyProjection` — wire-структура тела | — |
| `tags` | Metadata | `()` |
| `idempotent` | Явное replay-доказательство | выводится из method |
| `raw_response` | Вернуть normalized response | `False` |

Роутер объявляет `base_url`, `security`, `signing`, `crypto`, `wire`, `errors`, `unwrap`,
`protocol`, `signed` и `allow` обычными атрибутами класса; они наследуются по MRO, поэтому общий
для нескольких роутеров сервис описывается обычным базовым классом (см. {doc}`Мультисервисный SDK
</guides/multi-service>`).

## Запрос как значение

Связанная операция умеет строить запрос, менять его и отправлять — см. {doc}`Запрос как значение
</guides/requests/values>`:

```python
request = users.get_user.request(user_id=42)
await users.get_user.send(users.get_user.evolve(request, page=2))
```

## Подготовка без отправки

Bound operation поддерживает ту же sync/async форму через `.prepare(...)`:

```python
prepared = await users.get_user.prepare(
    user_id=42,
    options=PrepareOptions(resolve_managed=False),
)
```

`prepare` выполняет обычные bind/default/project/encode/sign стадии и останавливается на общей
границе перед handler send. Pure mode не вызывает providers и возвращает
`PreparationIncompleteError`, если нужны managed values. Full mode (`resolve_managed=True`)
использует test providers, но сеть всё равно не вызывается. `PreparedCall` редактирует secret
headers, cookies, query и private body.
