Protection имеет три независимых lifecycle. Они не используют общий untyped registry.

| Lifecycle | Config field | Когда выполняется |
|---|---|---|
| Mandatory operation flow | `operation_protections` | до конкретной operation |
| Proactive policy | `before_call_policies` | до каждого подходящего call/attempt |
| Conditional challenge | `challenge_policies` | после совпавшего response signal |

Auth остаётся отдельным механизмом в `ClientConfig.auth`.

First-party presets возвращают installable policy. Рекомендуемый config path:

```python target
config = ClientConfig(network_identity=identity).with_protection(
    cloudflare.challenge_pages(
        scope=host("api.example.test"),
        solver=CloudflareSolver(),
    )
)
```

`with_protection()` возвращает новый `ClientConfig`, детерминированно добавляет lifecycle policy и
solver binding и отклоняет duplicate policy identity или solver requirement. Исходный config не
изменяется. Unbound preset поддерживает SDK-level DI и падает с `MissingSolverError` на preflight.

## Mandatory operation flow

```python target
requirement = ProtectionRequirement[Result]("login-protection")
flow = protection_flow(
    requirement,
    acquire=ProtectionApi.acquire,
    solve=True,
    verify=ProtectionApi.verify,
)

config = ClientConfig(
    operation_protections=(flow,),
    operation_protection_solvers=SolverBindings(
        bind_solver(requirement, solver),
    ),
)
```

Operation по-прежнему объявляет `protections=(requirement,)`. `FromProtection` связывает typed
result с private target-моделью `BodyProjection`. Missing flow, solver или source field
отклоняются до main request.

## Conditional challenge

`ChallengePolicy[TChallenge, TSolution]` содержит точный `scope`, один `signal`, solver
requirement, `PrivateBindings`, persistence, replay policy, capability requirements и optional
solution-identity expectation. Для custom framework policy solver можно зарегистрировать через
advanced low-level collections:

```python target
config = ClientConfig(
    challenge_policies=(KAD_WASM_POLICY,),
    challenge_solvers=ChallengeSolverBindings(
        bind_challenge_solver(KAD_WASM_SOLVER, KadSolver()),
    ),
)
```

`private_header`, `private_query`, `private_cookie` и `private_body` резервируют wire targets в
compiler layout, но не добавляют параметры в public method signature. `private_cookie_set`
атомарно разворачивает именованный набор cookies, поэтому Cloudflare preset применяет все cookies
из `CloudflareClearance.cookies`.

## Persistence

Доступны `per_match`, `per_call`, `per_attempt`, `until_expiry` и `until_rejected`.
Shareable state ключуется identity/revision policy, solver, client/session/network scope и
объявленной challenge identity. Expiry всегда ограничивает reuse сверху. Повторный definitive
challenge инвалидирует применённую revision до replay.

Для одинакового полного ключа acquisition выполняется single-flight. Отмена solve не публикует
partial state. Все source fields и destinations валидируются до единственного immutable commit;
ошибка одного binding не меняет attempt или cache. Managed slots помечены secret и значения не
попадают в diagnostics.

## Network identity

| Type | Contract |
|---|---|
| `NetworkIdentity` | Immutable redacted identity: proxy label, User-Agent, address family and browser profile |
| `StaticNetworkIdentity` | Provider, который возвращает одно identity для всех attempts |
| `NetworkIdentityProvider.current(context)` | Возвращает identity для конкретных operation, attempt и URL |
| `NetworkIdentityExpectation` | Выбирает expected identity из typed solution до state publication |

`ClientConfig.network_identity` подходит custom handler. First-party handlers также принимают
`network_identity`; если config и handler задают разные источники, client отклоняет конфигурацию.
Для rotation один provider instance должен управлять connection profile handler-а и возвращать
runtime ту же redacted identity. Network-scoped policy без source падает с
`NetworkIdentityRequiredError` до providers и emit.

## Capabilities

`ProtectionCapabilities` разделяет requirements policy и capabilities solver-а. Preflight
проверяет `response_body`, `cookie_jar`, `javascript`, `browser` и `sticky_network_identity`.
`CapableChallengeSolver.capabilities` или явный `bind_challenge_solver(..., capabilities=...)`
объявляет возможности реализации. `ProtectionCapabilityMismatch` перечисляет только policy и
missing dimensions, без identity values или secrets.

## Exceptions and replay

- malformed policy или missing solver завершается до provider/transport I/O;
- binding conflict завершается на compiler preflight;
- missing solution field и invalid managed value вызывают `PlanError` без partial commit;
- replay выполняется только при доказанной `ReplayPolicy` safety и заново запускает projection,
  crypto, encoding и signing.

`ReplayPolicy.max_replays` не может быть отрицательным. Ноль отключает protection replay и не
уменьшает обычный attempt limit. `idempotency_key(name)` принимает только непустое валидное HTTP
field name; `proof_name` запрещён для остальных safety modes. Lifetime state задаётся только через
`ProtectionPersistence`.
