Установите extra `curl-cffi`:

```bash
uv add "eazy-sdk[curl-cffi]"
```

Передайте вариант браузера через `impersonate`. Он попадёт в профиль обработчика и станет
частью транспортной идентичности защиты:

```{literalinclude} ../../../../../../examples/docs/integration_curl_cffi.py
:language: python
:start-after: "# docs:integration-curl-cffi:start"
:end-before: "# docs:integration-curl-cffi:end"
```

:::{dropdown} Файл целиком
```{literalinclude} ../../../../../../examples/docs/integration_curl_cffi.py
:language: python
```
:::

<!-- example-output: examples.docs.integration_curl_cffi -->
```text
message: 42 План на пятницу
impersonation: chrome
```

Синхронный вариант строится через `Client.curl_cffi(...)`. Обе фабрики отключают собственные
cookies и перенаправления сессии, чтобы ими управлял общий исполнитель Eazy SDK.

`curl_cffi` нужен, когда сайт сравнивает TLS-отпечаток с ожидаемым браузером. Само значение
`impersonate` не доказывает совпадение с конкретным браузером навсегда: поддерживаемые варианты
и отпечатки зависят от установленной версии `curl_cffi`.

Готовую `Session` или `AsyncSession` передавайте через `session=`. В этом режиме `proxy=` и
`impersonate=` должны описывать реальную конфигурацию сессии, а закрывает её создавший код.
