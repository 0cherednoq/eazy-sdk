Аккаунт `captcha@mail.example` принимает пароль, но до второго фактора требует проверку
`mail-login`. Эта капча придумана для учебного сайта. Решатель меняет состояние текущего
клиента, после чего шаг пароля продолжается.

| Линия | Что делает решатель | Что продолжает работу |
|---|---|---|
| HTTP | кладёт `login_clearance=solved` в cookie | тот же POST повторяется по политике replay |
| Браузер | нажимает кнопку виджета | тот же вызов операции дожидается страницы кода |

::::{grid-item}

**→ Request** · ``POST /login/password``

```json
{
  "login_id": "login:captcha@mail.example",
  "password": "correct"
}
```

::::{grid-item}
:class: http-panel http-panel--response

**← Response** · ``403 Forbidden``

```json
{"kind": "captcha", "site_key": "mail-login"}
```

`LoginCaptchaGuard` распознаёт ответ до разбора обычных ошибок. Политика
`rejected_before_execution(max_replays=1)` разрешает ровно один повтор: сервер отклонил запрос
до выполнения входа, поэтому повтор не дублирует результат.

::::{tab-item} Браузер
:sync: browser

После отправки пароля `MailSite` возвращает этот фрагмент:

```html
<main data-page="captcha" data-login-id="login:captcha@mail.example"><div class="captcha" data-site-key="mail-login">Подтвердите вход</div><form method="post" action="/login/captcha"><input name="login_id" type="hidden" value="login:captcha@mail.example"><button data-action="solve" type="submit">Я не робот</button></form></main>
```

`Handle` проверяется раньше `Failure`. Он нажимает кнопку решения, страница переходит к форме
кода, и исход `to=OtpStep` завершает исходный вызов `password(...)`.

:::{note}
Повтор HTTP ограничен политикой replay. Браузер не отправляет пароль второй раз: обработчик
виджета остаётся внутри уже начатой операции и ждёт её обычный исход.
:::
