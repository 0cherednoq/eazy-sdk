title: Вход в три шага
description: Три операции проводят аккаунт от адреса почты до готовой сессии.

Вход не стоит прятать в один метод. После адреса сайт показывает форму пароля, после пароля
переводит на второй фактор и только после кода выдаёт сессию. Отдельная операция на каждый шаг
сохраняет этот порядок в типах.

| Шаг | Запрос или страница | Следующее состояние |
|---|---|---|
| Адрес | `POST /login/identify` или поле `email` | `PasswordStep` |
| Пароль | `POST /login/password` или поле `password` | `OtpStep` |
| Код | `POST /login/otp` или поле `code` | `Session` или `Mailbox` |

::::{tab-item} Браузер
:sync: browser

Браузерные операции заполняют по одной форме. После клика правило `when(...)` ждёт признак
следующей страницы, а `to=` строит состояние с тем же роутером.

После отправки адреса тот же `MailSite` возвращает страницу пароля:

```html
<main data-page="password">
  <form method="post" action="/login/password">
    <input name="login_id" type="hidden" value="login:ada@mail.example">
    <label>Пароль <input name="password" type="password"></label>
    <button type="submit">Войти</button>
  </form>
</main>
```

`PasswordStep` и `OtpStep` хранят тот же `LoginPortal`, поэтому вызывающему коду не нужно
пересобирать клиент между страницами. HTTP-линия передаёт `login_id`, браузерная сохраняет
контекст страницы; обе следуют одному порядку сайта.
