title: Обновление сессии без ручного повтора
description: Возьмите токен из HTML и обновляйте сессию по сроку или после отказа сайта.
freshness: false

Сессия живёт дольше одного запроса. Страница входящих уже содержит access-токен, refresh-токен и
срок действия. HTTP-клиент читает их как `MailSession`; браузер хранит ту же сессию в cookie
контекста. Прикладной код вызывает только защищённую операцию, а вход, обновление и повтор остаются
внутри жизненного цикла.

| Ситуация | Что видит сайт | Что делает SDK | Результат |
|---|---|---|---|
| Первый HTTP-запрос | сессии ещё нет | читает токены из HTML | `session-1` |
| Срок почти вышел | до `expires_at` меньше запаса | обновляет до запроса | `session-refresh-1` |
| Access-токен отвергнут | защищённая ручка отвечает `401` | обновляет и повторяет один раз | `session-refresh-2` |
| Две вкладки контекста | общая cookie `mail_session` | проводит один вход под локом | обе вкладки открыты |


Три поля одной Pydantic-модели выполняют две задачи. `CSS(...)` извлекает значения из HTML,
а `Bearer`, `RefreshToken` и `ExpiresAt` описывают их роль в сессии. Запас в десять секунд не
даёт отправить токен, который истечёт во время запроса.

```{literalinclude} ../../../../../examples/mail/http/session.py
:language: python
:start-after: "# region docs: http-session-model"
:end-before: "# endregion docs: http-session-model"
```

При первом защищённом вызове `MailSessionService.acquire` читает страницу входящих. Для
обновления сервис передаёт refresh-токен обычной незащищённой операции; access-токен туда не
нужен и не создаёт цикл авторизации.

```{literalinclude} ../../../../../examples/mail/http/session.py
:language: python
:start-after: "# region docs: http-session-service"
:end-before: "# endregion docs: http-session-service"
```

Один и тот же вызов `sdk.user.current()` показывает оба пути. Сначала часы пересекают локальный
срок, затем сайт забывает ещё живой access-токен и отвечает `401`.

```{literalinclude} ../../../../../examples/mail/http/session.py

:end-before: "# endregion docs: http-session-flow"
```

::::{tab-item} Браузер
:sync: browser

После успешного входа MailSite отдаёт страницу с таким фрагментом:

```html
<meta name="mail-token" content="session-ada">
```

`MailLoginService` проходит уже объявленные три шага и экспортирует состояние контекста.
`BrowserLogin` проверяет, что в нём появилась cookie `mail_session`; пустой результат входом не
считается.

```{literalinclude} ../../../../../examples/mail/browser/session.py
:language: python
:start-after: "# region docs: browser-session-login"
:end-before: "# endregion docs: browser-session-login"
```

`BrowserSession` создаётся на контекст, а не на вкладку. Два клиента с разными страницами получают
один объект сессии: параллельные первые переходы сходятся в один вход, затем обе вкладки используют
cookie контекста.

:::{note}
У `BrowserSession` один объект на один контекст. Для второго контекста создайте второй объект через
`login.session(...)`; общее хранилище может согласовать их ревизии, но не объединяет cookie jars.
