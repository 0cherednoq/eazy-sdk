Корень называет доступные роутеры и выбирает для каждого клиент. `MailSdk` собирает HTTP-группы
аккаунта и писем. `BrowserMailSdk` наследует их без повторного объявления и добавляет
`MailboxApi`, который работает на странице Chromium.

| Решение сборки | HTTP-запуск | Браузерный запуск |
|---|---|---|
| Корень | `MailSdk` | `BrowserMailSdk` |
| HTTP-клиент | HTTPX | curl_cffi с профилем Chrome 124 |
| HTTP-роутеры | `AccountApi`, `MessagesApi` | те же классы роутеров |
| Браузерный роутер | нет | `MailboxApi` через `bind(...)` |
| Сессия HTTP | статический Bearer для учебного запуска | токен из `mail_session` после одного входа в Chromium |

::::{tab-item} Браузер
:sync: browser

`BrowserLogin` входит один раз и отдаёт состояние контекста. `browser_cookie_auth(...)` извлекает
токен из `mail_session` и строит Bearer-авторизацию для тех же HTTP-операций. Реальный
`AsyncClient.curl_cffi(...)` отправляет запросы, а `bind(...)` оставляет `MailboxApi` на клиенте
Chromium.

Браузерный роутер ждёт `data-page="mailbox"`, а карта писем работает с коллекцией внутри него.
Обе метки приходят из фактического HTML учебного сайта:

:::{note}
Корень не владеет клиентом, переданным через `bind(...)`. Поэтому браузерный клиент закрывается
в `finally`, а HTTP-клиент, созданный контекстным менеджером, закрывается своим менеджером.
:::
