---
title: Чтение всех писем по частям
description: Обойдите один список через offset, cursor или next URL и подгрузите письма кнопкой.
freshness: false
---

Почта отдаёт по два письма. HTTP-клиент может следовать смещению, курсору или готовой ссылке;
браузер видит первую пару в HTML и просит страницу подгрузить вторую. Во всех четырёх случаях
результат один: письма `42`, `43`, `44` и `45` в исходном порядке.

| Вариант | Адрес следующей порции | Условие остановки |
|---|---|---|
| HTTP, `Pages.offset` | `offset + len(items)` | достигнут `total` |
| HTTP, `Pages.cursor` | `next_cursor` из ответа | курсор равен `null` |
| HTTP, `Pages.next_url` | готовый `next_url` | ссылка равна `null` |
| Браузер, `each(...)` | кнопка `data-action="more"` | четвёртый элемент появился в коллекции |

Три операции обращаются к одной ручке и разбирают одну модель ответа. Различается только
`__pages__`: стратегия называет поля запроса и функцию, которая читает указатель следующей
порции.

авторизацией, разбирает ответ обычным способом и отдаёт сообщения по одному.

::::{tab-item} Браузер
:sync: browser

Первая страница входящих содержит два элемента и кнопку:

```html
<ul data-collection="messages"><li data-message-id="42"><b>ada@mail.example</b> Планы на пятницу</li><li data-message-id="43"><b>grace@mail.example</b> Сверка протокола</li></ul><button data-action="more">Ещё</button>
```

`each(...)` связывает поле карты со всеми видимыми `li`. Сначала операция читает снимок
коллекции, затем нажимает кнопку и ждёт элемент с индексом `3`. После этого новый снимок уже
содержит обе порции.

```{literalinclude} ../../../../../examples/mail/browser/messages.py

:end-before: "# endregion docs: browser-message-collection"
```

:::{note}
`Elements.count()` и `Elements.texts()` читают снимок без ожидания. Когда нужен будущий узел,
обращайтесь к `nth(i)`: действие над ним ждёт появления элемента в пределах таймаута.
:::
