Письмо проходит две стадии. Сначала Eazy SDK преобразует `subject` и `body` внутри модели, затем
JSON-кодек создаёт байты и второй алгоритм шифрует их целиком. HMAC из предыдущей главы видит уже
шифротекст, поэтому сервер проверяет ровно те байты, которые получил.

| Стадия | Вход | Результат |
|---|---|---|
| Преобразование полей | `NewMessage.subject`, `NewMessage.body` | строки с префиксом `mail-field:` |
| JSON-кодек | модель с преобразованными полями | компактный UTF-8 JSON |
| Преобразование байтов | сериализованный JSON | байты с префиксом `mail-body:` |
| Подпись | окончательные байты | `X-Mail-Signature` по шифротексту |
| Входящий ответ | зашифрованные байты | обычный `SendResult` после обратных стадий |

Алгоритмы принадлежат приложению. Учебные реализации кодируют значение в Base64 с различимым
префиксом; `CryptoContext` они принимают по тому же протоколу, что и настоящий алгоритм из KMS
или хранилища ключей.

```{literalinclude} ../../../../../examples/mail/crypto.py

:end-before: "# endregion docs: mail-demo-ciphers"
```

Профиль задаёт порядок стадий и пределы размера. `encrypt_field(...)` получает тип модели и путь,
который проверяет типизатор. `encrypt_encoded(...)` работает позже, уже с сериализованными байтами.
Обратное преобразование байтов нужно для зашифрованного ответа.

```{literalinclude} ../../../../../examples/mail/http/encryption.py
:language: python
:start-after: "# region docs: mail-encryption-profile"
:end-before: "# endregion docs: mail-encryption-profile"
```

Операция связывает профиль с контрактом представления. Внешний `Content-Type` принадлежит зашифрованному
формату, а `clear_content_type` говорит декодеру, что после расшифровки лежит JSON.
`plaintext_statuses` оставляет ответы `401` и `403` открытыми: сервер возвращает такие отказы до
расшифровки тела. Подпись остаётся той же, но исполняется после обеих исходящих стадий.


расшифровал поле перед сохранением, а вызывающий получил обычную модель ответа.

::::{tab-item} Браузер
:sync: browser

JavaScript учебной страницы сам шифрует поля и тело перед `fetch` и расшифровывает ответ;
браузерная операция только заполняет форму и распознаёт
{doc}`три исхода композера </tutorial/send>`.
::::
:::::

:::{warning}
Base64 не обеспечивает секретность. Эти обратимые алгоритмы показывают места подключения;
в приложении передайте алгоритм с проверенной схемой, управлением ключами и уникальным `nonce`.
:::
