Управляемая сессия выполняет login перед первым защищённым вызовом. Приложение передаёт
`LoginCredentials`, а `LoginService` вызывает обычную объявленную операцию и возвращает
`UserSession`.

:::::{grid} 1 1 2 2
:class-container: http-exchange
:gutter: 2

::::{grid-item}
:class: http-panel http-panel--request

**→ Запрос** · ``POST /auth/login``

```json
{"email": "ada@mail.example", "password": "correct-horse"}
```
::::

::::{grid-item}
:class: http-panel http-panel--response

**← Ответ** · ``200 OK``

```json
{
  "access_token": "access-1",
  "refresh_token": "refresh-1",
  "expires_at": "2099-01-01T00:00:00Z"
}
```

Login и refresh остаются обычными публичными операциями, а защищённый роутер использует
`USER_SESSION` по умолчанию.

`acquire(...)` получает типизированный `context.sdk`. Корень объявляет обе группы один раз.

операцию уже с `Authorization`.

| Ответ login | Правило | Что получает вызывающий |
|---|---|---|
| `200` с моделью сессии | `acquire(...)` завершён | Результат защищённого метода |
| Отображённый `ApiError` | Сессия не сохранена | Типизированное исключение |
| Неизвестный или повреждённый ответ | Разбор модели не выполнен | Ошибка протокола |
