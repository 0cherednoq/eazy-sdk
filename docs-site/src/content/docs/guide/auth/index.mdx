Ключ, токен или сессия?

Авторизация состоит из схемы в контракте операции и источника данных в `Identity`. Схема
определяет место в запросе, а источник отдаёт ключ, пароль, токен или cookie во время вызова.

| Что требует сайт | Что использовать |
|---|---|
| Заголовок или параметр с ключом | {doc}`Передать API key </guide/auth/api-key>` |
| Логин и пароль в `Authorization` | {doc}`Передать Basic credentials </guide/auth/basic>` |
| Готовый access token | {doc}`Передать Bearer token </guide/auth/bearer>` |
| Готовую session cookie | {doc}`Передать session cookie </guide/auth/cookie>` |
| JWT без клиентской проверки claims | {doc}`Передать JWT </guide/auth/jwt>` |
| Несколько обязательных или альтернативных схем | {doc}`Собрать требования AND и OR </guide/auth/combined>` |
| Получение, обновление и повторное использование сессии | {doc}`Войти и получить сессию </guide/auth/login>` |

Статическая схема подходит, когда credential уже известен и не меняется внутри SDK. Для входа,
обновления по сроку или после `401` используйте управляемую сессию.
