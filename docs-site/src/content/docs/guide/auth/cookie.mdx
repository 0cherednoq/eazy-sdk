`CookieScheme` подходит, когда значение session cookie уже известно. Имя cookie задаётся в
схеме, а значение хранится в `Identity`.

:::::{grid} 1 1 2 2
:class-container: http-exchange
:gutter: 2

::::{grid-item}
:class: http-panel http-panel--request

**→ Запрос** · ``GET /auth/cookie``

```json
{"headers": {"Cookie": "mail_session=session-1"}}
```
::::

::::{grid-item}
:class: http-panel http-panel--response

**← Ответ** · ``200 OK``

```json
{"credential": "session-1"}
```
::::
:::::

```{literalinclude} ../../../../../../examples/docs/auth_cookie.py
:language: python
:start-after: "# region docs: auth-cookie"
:end-before: "# endregion docs: auth-cookie"
```

`CookieScheme("mail_session")` управляет только объявленным значением. Обычные cookies клиента
могут существовать рядом, но не удовлетворяют `security=MAIL_SESSION` без источника в `Identity`.

Если cookie выдаёт браузер после интерактивного входа, используйте мост браузерной сессии из
{doc}`главы о сборке SDK </tutorial/assembly>`, а не копируйте заголовок вручную.
