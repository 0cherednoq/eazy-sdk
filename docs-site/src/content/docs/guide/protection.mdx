Guard нужен, когда сайт вместо обычного ответа возвращает защитную проверку. Он распознаёт
помеху, вызывает типизированный solver, применяет решение и заново готовит исходный запрос в той
же транспортной сессии.

## Выбрать готовую защиту

Установите пакет с поддерживаемыми пресетами:

```bash
uv add eazy-sdk-presets
```

Готовые страницы описывают настройку {doc}`Cloudflare Challenge Pages
</integrations/protection/cloudflare>`, {doc}`Turnstile </integrations/protection/turnstile>` и
{doc}`reCAPTCHA </integrations/protection/recaptcha>`. Пресет устанавливается в корне SDK через
`ClientConfig(security=Security.of(guard))`.

## Настроить область, хранение и повтор

| Атрибут | Назначение |
|---|---|
| `scope` | Ограничивает правило хостом, операцией или другим `RequestScope` |
| `cache="none"` | Решение не покидает текущую попытку |
| `cache="call"` | Решение повторно используется только внутри одного вызова |
| `cache="session"` | Решение разделяется вызовами одной транспортной сессии |
| `replay` | Задаёт доказательство безопасности и число повторов |
| `revision` | Отделяет новое правило от ранее сохранённых решений |

`headers`, `query` и `body` объявляют назначения, которые разрешено менять решению. Для cookie
отдельное разрешение не требуется. Кэш можно очистить методом `client.invalidate_protection(...)` для
конкретного guard, имени политики или всей сессии.

## Решать в той же транспортной сессии

`context.fetch(...)` загружает вспомогательный ресурс через тот же handler, proxy и cookie jar.
Такой запрос обходит guards, middleware, rate limit и повтор, поэтому solver не вызывает сам себя.
Каждый полученный `Set-Cookie` остаётся в сессии защищённого вызова.

`context.identity` описывает `User-Agent`, объявленный proxy и метку impersonation. Сохранённое
решение привязано к этому отпечатку и сбрасывается при смене сетевой личности.

:::{warning}
Если solver использует отдельный браузер или HTTP-клиент вместо `context.fetch(...)`, он сам
должен сохранить тот же proxy, `User-Agent`, TLS-отпечаток и cookies.
:::

## Разобрать ошибку стадии

| Ошибка | Стадия |
|---|---|
| `ProtectionConfigurationError` | Некорректная схема до транспортного вызова |
| `ChallengeDetectionError` | Неожиданная ошибка detector |
| `ChallengeParseError` | Помеха распознана, но её данные повреждены |
| `ChallengeSolveError` | Solver не получил решение |
| `ChallengeApplicationError` | Решение нельзя безопасно применить |
| `ReplayDeniedError` | Нет доказанного или доступного повтора |

Ошибки сохраняют исходное исключение в `__cause__`, но не включают тело ответа, cookies или
credentials в собственное сообщение. Низкоуровневые контракты генераторов находятся в
`eazy_sdk.protection.advanced`; прикладному SDK обычно достаточно `Guard` или готового пресета.
