| Статус | Следующий method | Тело |
|---|---|---|
| `301`, `302` | По redirect policy | Обычно удаляется при переходе на `GET` |
| `303` | `GET` | Удаляется |
| `307`, `308` | Сохраняется | Требует replay-safe body |

Каждый переход повторно применяет scoped middleware, авторизацию, подготовку и подпись.
Неожиданный authority не получает credentials автоматически. Исчерпание `max_redirects` приводит
к `RedirectLimitError`.

`Resilience(max_redirects=N, client_redirects=True)` добавляет к статусам переход, записанный в
странице тегом `<meta http-equiv="refresh">`. Он выполняется запросом `GET`, расходует тот же
запас и срабатывает, только если страницу не приняла ни одна модель операции. Тег внутри
`<noscript>`, задержка больше пяти секунд и адрес самой страницы переходом не считаются. Переход
через `window.location` требует исполнения скрипта и клиентом не выполняется.

На сайте с объявленными `Cookies(...)` каждый шаг перехода получает куки, которые поставили
предыдущие шаги, и только те, что предназначены его хосту.

Клиент следует только тем переходам, на статус которых операция не объявила случай. Если исход
вызова записан в адресе перехода, объявите его в операции, и ответ достанется ей. Подробнее об
этом рассказывает руководство {doc}`о чтении исхода из адреса перехода </guide/responses/redirects>`.
