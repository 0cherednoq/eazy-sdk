Ожидаемый отказ входит в контракт операции. Объявите модель тела, наследника `ApiError` и
соответствие в `errors=`. Вызывающий сможет обработать каждый исход отдельным `except`, без
ветвления по числовому статусу.

| Ответ сайта | Правило операции | Что получает вызывающий |
|---|---|---|
| `200` с заказом | `HttpOperation[Order]` | `Order` |
| `404` с проблемой | `errors={404: OrderNotFound}` | `OrderNotFound` |
| `429` с проблемой | `errors={429: RateLimited}` | `RateLimited` |

`ApiError[ApiProblem]` сохраняет типизированное тело в `.error`. Свойство `.summary` содержит
безопасную сводку: идентификатор операции, статус, тип содержимого, номер попытки, метод и
отредактированный адрес. Полный контекст ответа остаётся в `.context`.

## Разместить общие ошибки

Операция объявляет собственные ошибки. Роутер добавляет отказы всего сервиса через `errors`, а
`ClientConfig(errors=...)` задаёт ответы конкретного хоста. При совпадении выигрывает объявление,
которое находится ближе к операции.

Условие `when=` различает ответы с одинаковым статусом по телу, заголовку или типу содержимого.
Предикаты из `eazy_sdk.response.match` проверяют сырые байты до разбора модели. Неизвестный ответ
даёт `UnexpectedResponseError`, а неверное тело уже выбранного случая даёт
`MalformedResponseError`.
