Алгоритм принадлежит приложению.

Eazy SDK задаёт порядок преобразований, но не поставляет cipher, keyring или KMS-клиент.
Алгоритм, ключи, nonce и их ротация остаются в приложении.

## Порядок стадий

```text
исходящий: модель → поля → кодек → байты → подпись → отправка
входящий: ответ → байты → кодек → поля → проверка модели
```

Подпись видит ciphertext, если операция использует и шифрование, и signing. Каждая повторная
попытка заново выполняет преобразования, поэтому nonce и ciphertext предыдущей попытки не
переиспользуются.

Для WebSocket укажите `websocket_encrypted(...)`. Шифрование всего frame обычно требует binary
frame; text разрешён только для алгоритма, который гарантирует валидный UTF-8, тогда как ping,
pong и close остаются управляющими frames и вообще не проходят payload crypto.

Typed metadata для key id или nonce объявляется через `CryptoResult` и связывается с конкретным
wire-slot. Необъявленное, пропущенное или конфликтующее значение приводит к закрытой ошибке.
