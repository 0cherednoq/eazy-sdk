Зависимость подходит для значения, которым владеет приложение, а не вызывающий код. Автор SDK
объявляет тип и назначение, приложение регистрирует provider, а runtime разрешает значение перед
подготовкой запроса.


`DEVICE` выбирает поле `id` результата и пишет его в объявленный `X-Device-Id`. Поле операции
имеет `UNSET` по умолчанию, поэтому provider заполняет его только тогда, когда вызывающий не
передал значение сам.

`DependencyRegistry` принадлежит `Identity` и обслуживает все роутеры корня. Отсутствующий
обязательный provider останавливает вызов до сети.

## Выбрать способ применения

| Способ | Когда использовать |
|---|---|
| `Inject(...)` | Значение целиком занимает новый header, query, cookie или поле тела |
| `requires=` с `apply=` | Значение заполняет уже объявленный слот операции |
| `requires=` с `BodyProjection` | Значение нужно внутри private wire-документа |

## Выбрать срок кэша

| Политика | Когда provider вызывается снова |
|---|---|
| `NONE` | При каждом обращении к зависимости |
| `CLIENT` | После создания нового роутера |
| `CALL` | Для нового логического вызова |
| `ATTEMPT` | Для каждой попытки, включая retry и redirect |

Nonce и timestamp обычно требуют `ATTEMPT`, а неизменяемый device context можно хранить с
`CLIENT`. Маркер `secret=True` скрывает значение из диагностики.

:::{note}
Access token относится к авторизации, captcha к защите, а ключ HMAC к `key_provider`. У этих
значений другой жизненный цикл, поэтому не оформляйте их как обычные зависимости.
:::
