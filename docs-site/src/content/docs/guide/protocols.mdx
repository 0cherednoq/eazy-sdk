Конверт не является сетевым транспортом.

Он добавляет к полезной нагрузке method, correlation id и служебные поля. Конверт принадлежит
сервису, поэтому объявляется на роутере и применяется ко всем его RPC-операциям.

операции становятся `params`. Публичный вызов остаётся обычным типизированным методом.

## Место конверта в запросе

```text
модель → проекция → конверт → кодирование → шифрование байтов → подпись
```

Подпись и шифрование всего payload получают конверт целиком. Значение JSON-RPC `id` по умолчанию
сохраняется при retry, чтобы сервер мог распознать дубликат. Для сервиса, который требует новый
идентификатор, укажите `id_on_retry="regenerate"`.

JSON-RPC обычно сообщает ошибку внутри ответа `200`. `rpc_result(...)`, `rpc_error(...)` и
`rpc_error_default(...)` превращают result и error в обычные response cases, поэтому вызывающий
получает тот же `ApiError`, что и у REST.

Пакетный JSON-RPC вызов не входит в прозрачный runtime. Частичный успех нарушает соответствие
одной операции одному типизированному результату, а повтор всего batch больше нельзя считать
безопасным только по свойствам отдельных элементов.
