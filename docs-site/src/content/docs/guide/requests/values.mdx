Метод `request(...)` создаёт неизменяемое значение операции без сети. Сохраните его в очереди,
измените через `evolve(...)`, затем отправьте методом `send(...)`.

:::::{grid} 1 1 2 2
:class-container: http-exchange
:gutter: 2
::::{grid-item}
:class: http-panel http-panel--request
**→ Request** · ``GET /items?page=1&perPage=2``
::::
::::{grid-item}
:class: http-panel http-panel--response
**← Response** · ``200 OK``
```json
{"items": ["keyboard", "mouse"], "next_page": 2}
```
::::
:::::

`request(...)` использует конструктор `ListItems`, поэтому применяет те же значения по умолчанию
и проверяет те же обязательные поля, что прямой вызов `list_items(...)`.

```{literalinclude} ../../../../../../examples/request_values.py
:language: python
:start-after: "# docs:flow:start"
:end-before: "# docs:flow:end"
```

`evolve(request, page=...)` возвращает новое значение через адаптер модели. Исходный запрос не
меняется. `send(request)` выполняет его, а обычный список хранит очередь без отдельной абстракции.

Для настроек одного вызова передайте `options=` в `send`. Метод `send_with_response` вернёт
`ResponseEnvelope` вместе с типизированным значением, как и `.with_response` у прямого вызова.
