## Если API уже описан схемой

Для OpenAPI используйте {doc}`генератор OpenAPI </integrations/generators/openapi>`. Он создаёт
Python-пакет SDK из схемы и сохраняет типы запросов и ответов.

Для AsyncAPI и WebSocket начните с {doc}`руководства по WebSocket </guide/websocket>`. Там
показаны генерация пакета, подключение клиента и типизированные сообщения.

## Документация для LLM

Сборка сайта создаёт два текстовых файла из тех же страниц:

- <a href="/llms.txt"><code>llms.txt</code></a> содержит краткое описание проекта и ссылки на
  страницы;
- <a href="/llms-full.txt"><code>llms-full.txt</code></a> содержит полный текст документации в
  одном файле.

Выбор зависит от инструмента.

Передайте помощнику `llms.txt`, если он умеет открывать ссылки: так в контекст попадут только
нужные страницы. `llms-full.txt` подходит для локального поиска или инструмента, который не
может переходить по ссылкам. Оба файла обновляются при каждой сборке сайта, поэтому отдельную
копию документации поддерживать не нужно.

Для точной сигнатуры после объясняющей страницы откройте {doc}`справочник API
</reference/api/index>`. Он отделяет публичные имена от внутренних деталей реализации.
