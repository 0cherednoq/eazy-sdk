## Что произошло

`GetMessage` хранит описание GET-запроса. Поле `message_id: Path[int]` принимает число от
вызывающего кода и подставляет его в `/messages/{message_id}`. Тип
`HttpOperation[Message]` выбирает модель успешного ответа.

Библиотека моделей меняет только объявление `Message`.

`MailApi` публикует операцию под именем `message` и задаёт адрес сервиса. Вызов
`MailApi(client).message(message_id=42)` имеет ту же сигнатуру, что и класс `GetMessage`, поэтому
редактор кода знает имя и тип аргумента до запуска программы.

Функция `quickstart_client()` подключает пример к локальному учебному сайту из репозитория. В
прикладном SDK приложение создаёт `Client`, а роутер получает его готовым. Выбор HTTPX,
Requests или curl_cffi не меняет объявление операции.

## Следующий запрос

Для POST добавьте поля тела с маркером `JsonField`. Вложенную структуру внешнего JSON собирает
`BodyProjection`; вызывающему коду по-прежнему передаются обычные именованные аргументы. Эти
механизмы разобраны в {doc}`руководстве по запросам </guide/requests/index>`.

Когда методов станет несколько, объедините роутеры в корень SDK. Дальше можно изучить
{doc}`структуру запросов </guide/requests/index>`, {doc}`HTTP-интеграции </integrations/http/index>`
или {doc}`всё руководство </guide/index>`.
